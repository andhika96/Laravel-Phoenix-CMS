## 2026-07-18T02:50:45.004Z

Iya, benar—di mobile seharusnya membuka drawer tidak membuat tabel menghitung ulang layout karena sidebar hanya overlay dan tidak mengurangi lebar konten.

Penyebabnya:

- Aurora memanggil `notifyLayoutResize()` setiap sidebar dibuka/ditutup di [arunika_aurora.js](D:/Laragon/www/laravel-13-phoenix/public/assets/js/themes/arunika_aurora/arunika_aurora.js:127).
- Canvas melakukan hal yang sama di [arunika_canvas.js](D:/Laragon/www/laravel-13-phoenix/public/assets/js/themes/arunika_canvas/arunika_canvas.js:130).
- Fungsi tersebut mengirim event `window.resize` dua kali: langsung dan 280ms kemudian.
- Manage Article merespons perubahan ukuran dengan mengosongkan state kolom, mengukur ulang header, lalu menjalankan `recalcResponsive()` di [vueV3-manage-article-2026.js](D:/Laragon/www/laravel-13-phoenix/public/assets/js/vue3/manage_article/vueV3-manage-article-2026.js:1539). Inilah yang terlihat seperti tabel re-render.

Jadi itu kemungkinan bukan mengambil data API ulang, melainkan Vue menggambar ulang struktur kolom responsif.

Solusi yang tepat adalah membatasi `notifyLayoutResize()` hanya untuk desktop:

```js
if (window.innerWidth > 768) {
    notifyLayoutResize();
}
```

`ResizeObserver` Manage Article tetap dipertahankan karena masih diperlukan untuk perubahan ukuran viewport yang nyata, seperti rotasi perangkat atau resize desktop. Yang dihentikan hanya resize buatan ketika membuka drawer mobile.

Belum ada file yang saya ubah pada pemeriksaan ini. Kalau Anda setuju, saya bisa langsung menerapkan fix terarah tersebut pada Aurora dan Canvas.
