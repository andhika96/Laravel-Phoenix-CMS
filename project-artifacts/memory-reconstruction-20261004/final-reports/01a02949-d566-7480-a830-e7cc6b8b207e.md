## 2026-08-22T14:53:21.183Z

Maksud saya sebelumnya perlu diluruskan: tidak semua sepuluh modul memiliki Advanced sendiri karena membutuhkan opsi tambahan khusus. Penyebabnya campuran antara implementasi legacy, duplikasi, dan beberapa kebutuhan khusus layout.

| Modul | Isi Advanced saat ini | Kesimpulan |
|---|---|---|
| Divider, Icon, Spacer, Text Editor, Video | Hanya `CSS Class` | Bukan opsi khusus; ini Advanced versi lama yang sangat minimal |
| Button | Hanya `CSS Class`, tetapi memakai key `className` untuk elemen tombol | Semantik khusus tombol, bukan generic class pada wrapper |
| Container / Container Fluid | Layout, Motion Effects, Transform, Responsive, Attributes, Custom CSS | Campuran kontrol universal dan variasi khusus layout |
| Grid / Row Grid | Motion Effects, Positioning, Overflow, Responsive, Attributes, Custom CSS | Campuran kontrol universal dan kontrol seperti `Overflow` yang memang khusus layout |

Contohnya, [Button Settings](D:/Laragon/www/laravel-13-phoenix/public/js/pagebuilder_elementor_v24/widgets/basic/button/Settings.vue:41) hanya mempunyai blok Attributes/CSS Class. Sementara [Container Settings](D:/Laragon/www/laravel-13-phoenix/public/js/pagebuilder_elementor_v24/widgets/layout/container/Settings.vue:739) dan [Grid Settings](D:/Laragon/www/laravel-13-phoenix/public/js/pagebuilder_elementor_v24/widgets/layout/grid/Settings.vue:223) memiliki implementasi Advanced lama yang jauh lebih besar.

Sebagian besar isinya sebenarnya tumpang tindih dengan [AdvancedControls.vue](D:/Laragon/www/laravel-13-phoenix/public/js/pagebuilder_elementor_v24/widgets/shared/AdvancedControls.vue:1), tetapi memakai nama setting dan struktur UI berbeda, misalnya:

- Layout lama: `scrollEffectType`, `mouseEffectType`, `stickyOnDesktop`, dan `scrollRelativeTo`.
- Shared Advanced: `verticalScrollEnabled`, `mouseTrackEnabled`, `sticky`, dan `effectsRelativeTo`.
- Grid mempunyai `overflow`, yang belum tersedia di shared Advanced.
- Button memakai `className`, sedangkan shared Advanced memakai `cssClass`.

Jadi nantinya kita tidak boleh sekadar menghapus blok Advanced tersebut lalu menggantinya secara buta. Kontrak refactornya sebaiknya:

1. Kontrol universal dipindahkan ke satu `AdvancedControls.vue`.
2. Opsi yang benar-benar khusus, seperti `Overflow` atau sticky per-device, tetap dirender oleh file shared berdasarkan `capabilities/profile` yang dideklarasikan modul.
3. Key legacy tetap dinormalisasi atau diberi compatibility adapter agar halaman lama tidak berubah.
4. Tidak ada `Settings.vue` widget yang menyimpan salinan markup kategori Advanced sendiri.

Jadi jawaban singkatnya: sebagian kecil memang mempunyai kebutuhan khusus, tetapi keberadaan sepuluh implementasi terpisah itu terutama karena perkembangan source secara bertahap—bukan karena semuanya wajib memiliki file Advanced tersendiri.

Pemeriksaan ini baru verifikasi statis source aktual; tidak ada file aplikasi yang diubah dan tidak diperlukan browser QA pada tahap penjelasan ini.

Saat ini file masih terpisah di beberapa lokasi:

Untuk target 100% modular, saya merekomendasikan satu canonical module root:

```text

│   ├── layout/

│       │   └── ...
│       └── pro/
│           ├── form/
│           ├── hero-banner/
│           ├── media-carousel/
│           └── ...
└── shared/

```

Setiap folder modul akan memiliki paket lengkap:

```text
button/
├── module.json
├── definition.js
├── Canvas.vue
├── Settings.vue
├── frontend.blade.php
├── runtime.js          # hanya jika diperlukan
└── styles.css          # hanya jika diperlukan
```

`AdvancedControls.vue` berada di luar seluruh folder widget karena merupakan dependency core bersama.

Cara plug/unplug:

1. `ModuleDiscovery` memindai seluruh `module.json`.
2. Hanya modul valid yang dimasukkan ke registry, sidebar, loader, dan frontend renderer.
3. Folder `button/` dipindahkan keluar dari `modules/` atau dihapus → Button tidak ditemukan → langsung hilang dari sidebar setelah reload.
4. Folder dikembalikan → otomatis muncul kembali.
5. Data halaman lama yang memakai modul nonaktif tidak dihapus; frontend menampilkan marker `Unsupported/Inactive module` agar data tetap bisa dipulihkan.

Core editor seperti `app.js`, registry engine, module discovery, shared Advanced, clipboard, history, drag/drop, dan responsive engine tidak ikut berada dalam folder widget.

Alternatif lebih ringan adalah mempertahankan JS dan Blade di lokasi terpisah seperti sekarang, tetapi itu hanya modular pada sidebar—bukan full-stack 100%. Karena target Anda benar-benar modular, saya merekomendasikan struktur canonical module root di atas.
