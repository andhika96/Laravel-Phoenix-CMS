Ya, saya lihat. Untuk kasus di screenshot itu **jangan pakai horizontal scroll dulu**. Scroll X akan terasa kurang rapi untuk preview modal dan bisa bikin user mengira frontend aslinya juga butuh scroll.

Yang lebih tepat: **preview Mega Menu dibuat “fit inside preview canvas”**, bukan dibiarkan melebar lalu dipotong. Akar masalahnya ada di area preview: canvas memakai `overflow: hidden`, stage fixed `1180px` + scale, lalu Mega `container` dibuat hampir full-stage. Akibatnya sisi kiri konten/item pertama bisa kelihatan terpotong.

Rekomendasi saya:
1. Untuk preview saja, Mega `container/full` tetap terlihat lebar, tapi beri inset/padding aman dan hitung ulang `left + width` berdasarkan ukuran canvas preview aktual.
2. Jangan tambah scroll X kecuali untuk mode `custom` yang memang user sengaja bikin width besar.
3. Kalau item/card terlalu mepet, tambahkan sedikit inner padding/guard pada `.ph-preview-mega-dropdown` atau clamp posisi shell supaya isi tidak nempel ke sisi kiri canvas.

Jadi solusi paling bersih: **patch CSS + kalkulasi preview**, bukan scroll X global. Frontend publik jangan ikut diubah dulu kecuali nanti terlihat masalah sama di halaman asli.

Kalau kamu setuju, saya bisa langsung patch bagian preview saja: backup file terkait dulu, lalu ubah `frontend-menu-dropdown.css` dan kemungkinan kecil `dropdownPreviewShellStyle()` di JS supaya Mega Menu preview tidak kepotong.
