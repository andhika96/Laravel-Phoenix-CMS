## 2026-08-12T13:10:14.886Z

Progress Tracker berbeda dengan Progress Bar.

- Progress Bar menampilkan nilai statis, misalnya 75%.
- Progress Tracker membaca posisi scroll halaman/post, lalu mengisi indikator dari 0–100%.

Elementor memang menyediakan target tracking: Entire Page, Post Content, atau CSS Selector. Bentuknya bisa horizontal atau circular. [Dokumentasi resmi Progress Tracker](https://elementor.com/help/progress-tracker/)

Jadi ketika hanya mengubah bentuk menjadi lingkaran tetapi tetap kosong, biasanya penyebabnya:

1. `Progress Relative To` belum diset ke `Entire Page`.
2. Widget sedang dilihat di editor, bukan Preview/live page yang memiliki konteks scroll.
3. Halaman atau target selector tidak memiliki tinggi/isi yang bisa discroll.
4. Warna indikator sama dengan background, atau ukuran/width indikator terlalu kecil.
5. Widget belum dibuat sticky/positioned sehingga posisinya berada di area yang tidak terlihat.

Untuk mencoba di demo Elementor:

- Set `Tracker Type: Circular`.
- Set `Progress Relative To: Entire Page`.
- Aktifkan `Percentage`.
- Beri warna indikator dan background yang kontras.
- Set ukuran sekitar 40–60 px dan width sekitar 4–8 px.
- Buka Preview, lalu scroll halaman panjang tersebut.

Kalau tetap kosong di Preview setelah konfigurasi itu, kemungkinan preview Progress Tracker di demo Elementor tidak menginisialisasi konteks scroll dengan benar. Widget ini memang dirancang sebagai indikator kemajuan membaca/scroll, bukan elemen visual biasa di dalam flow halaman. [Penjelasan Elementor](https://elementor.com/blog/announcing-scroll-snap-and-progress-tracker/)

Untuk Page Builder v2.3, widget ini perlu diperlakukan khusus: page-level scroll listener, target selector resolver, sticky/fixed positioning, dan fallback visual di editor. Belum ada source yang saya ubah.

Solusi terbaik menurut saya adalah hybrid:

- Satu shared shell/context-menu di `app.js`.
- Daftar item tetap terpisah berdasarkan tipe:

```js
const contextMenuDefinitions = {
  widget: [...],
  container: [...],
  grid: [...],
  gridColumn: [...],
};
```

Jadi ini bukan satu menu universal. Widget tetap mendapat menu widget, Container mendapat menu Container, Grid mendapat menu Grid. Yang dipakai bersama hanya kerangka visual dan perilaku umum.

Dengan pola ini, jika nanti widget tertentu punya menu khusus, cukup menambahkan definisi/action-nya tanpa menyalin seluruh komponen menu.

Jadi rekomendasi final saya: light Phoenix design + shared shell + konfigurasi menu terpisah per tipe node. Belum ada source yang diubah pada tahap ini.
