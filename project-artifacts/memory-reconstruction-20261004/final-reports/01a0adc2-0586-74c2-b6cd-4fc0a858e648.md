**Jangan langsung mengikuti saran `git reset --hard` pada pesan tersebut.** Kita perlu mengamankan perubahan VPS dan memeriksa apakah percobaan sebelumnya meninggalkan proses merge/rebase yang belum selesai.

Jalankan pemeriksaan berikut di terminal VPS. Perintah ini hanya membaca kondisi repository:

```bash
cd /www/wwwroot/itbumdev.web.id

git status
git branch -vv
git diff --stat
git diff --cached --stat
git ls-files --others --exclude-standard
git log --oneline --left-right HEAD...origin/main -12
```

Kirim hasilnya, terutama **`git status`**. Status lokal yang sebelumnya saya periksa tidak bisa dipakai untuk menentukan kondisi VPS.

Setelah statusnya diketahui, jalur penyelesaiannya adalah:

1. **Backup perubahan VPS**, termasuk file baru yang belum dilacak.
2. Jika tidak ada merge/rebase aktif, simpan sementara perubahan tersebut. Untuk kasus ini, penyimpanan harus mencakup **untracked files**, bukan hanya perubahan file lama.
3. Tarik commit dari repo.
4. Bandingkan perubahan VPS yang disimpan dengan versi repo. **Jangan langsung menerapkan kembali semuanya**, karena file Kegiatan Lainnya dari VPS mungkin merupakan salinan versi lama dan bisa mengembalikan UI yang baru kita perbaiki.
