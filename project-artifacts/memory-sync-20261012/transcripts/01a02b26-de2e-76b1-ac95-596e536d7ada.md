# Rencana Implementasi Product Lead Form v2.4

## Ringkasan

Membuat widget Pro baru **Product Lead Form** berdasarkan struktur [MG Test Drive](https://www.mgmotor.id/testdrive), tetapi dengan tema netral dan kontrol penuh Page Builder. Widget merupakan fork independen dari Form lama, sedangkan engine submit, dataset, CKFinder, email, dan Advanced Controls tetap digunakan bersama.

Tidak ada migrasi database baru. Jumlah module menjadi **50**, terdiri dari **48 toolbox module** dan 2 hidden compatibility module.

## Kontrak dan Interface

- Module baru berada di `resources/pagebuilder_elementor_v24/modules/widgets/pro/product-lead-form/`.
- Manifest:
  - type `product_lead_form`;
  - label `Product Lead Form`;
  - category `pro`, order `15`;
  - icon `fas fa-clipboard-list`;
  - capabilities `form-submission`, `form-fields`, `draft-form`, `form-datasets`, `product-selection`, dan `pro-icon-targets`.
- Seluruh file Form di-clone lalu di-fork menjadi `definition.js`, `Canvas.vue`, `Settings.vue`, `frontend.blade.php`, `runtime.js`, `logic.js`, dan `styles.css`; module baru tidak mengimpor source runtime Form lama.
- Settings produk memakai:
  - `productData: { datasetMode: "dataset", datasetId }`;
  - `productLevelCount` bernilai 1–3;
  - tiga konfigurasi level dengan `label`, `fieldId`, `queryKey`, `presentation`, `required`, dan `defaultNodeId`;
  - default Model=Cards, Tipe=Select, Varian=Select.
- Node dataset tetap memakai `id`, `parentId`, `label`, `code`, `value`, dan `kind`.
  - `code` adalah slug query URL yang unik secara case-insensitive pada levelnya.
  - `value` adalah nilai submission.
  - `meta` menyimpan `thumbnailSource`, `thumbnailUrl`, `thumbnailAlt`, `imageSource`, `imageUrl`, `imageAlt`, `description`, `detailUrl`, dan `detailLabel`.
- Tidak ada aset MG yang disalin ke project.

## Perubahan Implementasi

1. **Pengamanan awal dan baseline**
   - Periksa ulang `git status`, source aktif, module count, dan Graphify.
   - Backup setiap file lama yang akan disentuh ke `project-artifacts/backups/pagebuilder-v24-product-lead-form_<timestamp>/`, lengkap dengan struktur path dan hash.
   - Tambahkan failing tests sebelum setiap perubahan produksi; jangan reset, clean, broad-stage, commit, atau push.

2. **Module, editor, dan dataset manager**
   - Fork Form lama sebagai module baru tanpa mengubah defaults atau perilaku Form lama.
   - Pertahankan seluruh Form Row Grid, field types, multi-step, conditional logic, custom messages, actions, dan Style Form.
   - Tambahkan panel Content untuk shared product dataset, 1–3 level, label/field/query key, Cards/Select, default selection, detail produk, posisi media, dan preview selection.
   - Buat Product Dataset Manager milik module baru yang memakai endpoint dataset lama, tetapi menambahkan editor metadata produk, CKFinder/URL picker, JSON manager, validasi hierarchy, unique `code`, serta peringatan bahwa dataset bersifat shared.
   - Dataset field biasa milik Form tetap memakai manager lama dan tidak berubah.

3. **Canvas, frontend, dan styling**
   - Selector tampil di atas; area bawah berisi media/detail dan Form dua kolom.
   - Posisi media responsif: kiri/kanan pada desktop-tablet dan atas/bawah pada mobile; default mengikuti MG dengan media kiri dan di atas pada mobile.
   - Setiap level Cards memiliki Style mandiri untuk layout, columns/min-width, gap, typography, border type/width/color/radius, background, shadow, serta state Normal/Hover/Selected.
   - Thumbnail dan gambar utama memiliki ukuran, resolution, width/height, object-fit, object-position, border, radius, dan shadow responsif.
   - Media/detail yang kosong diwarisi dari ancestor terdekat; bila seluruh rantai kosong, tampilkan kartu teks tanpa placeholder gambar palsu.
   - Gunakan radio group semantik untuk Cards, native `<select>` untuk Select, keyboard/focus state, label, alt text, dan ARIA status.
   - Editor hanya mengubah preview lokal; URL editor tidak boleh dimutasi.

4. **Deep-link dan data flow**
   - Frontend membaca key configurable dengan default `model`, `type`, dan `variant`.
   - Prioritas selection: query valid → configured default → item aktif pertama.
   - `?type=...` atau `?variant=...` dapat berdiri sendiri; runtime menemukan node unik lalu memilih seluruh ancestor.
   - Pemilihan pengunjung memperbarui URL melalui `history.replaceState`, mempertahankan query lain dan hash tanpa reload.
   - Parameter invalid/ambigu, node inactive, atau parent chain rusak memakai fallback dan menormalisasi URL ke selection valid.
   - Mengubah parent mereset descendants ke default valid atau item aktif pertama.
   - Dataset kosong/terhapus menghasilkan configuration state yang aksesibel dan menonaktifkan submit bila level wajib belum valid.

5. **Core submission bersama**
   - Tambahkan API internal `ModuleCatalog::supports(type, capability)` dan pemeriksaan “any active module supports capability”.
   - Ubah endpoint submit/draft dan dataset agar memeriksa capability module aktual, bukan hard-coded type `form`; URL endpoint lama tetap kompatibel.
   - Tambahkan resolver product selection di `app/Support/PageBuilderElementorV24/` untuk memuat dataset milik page owner, memvalidasi active node, value, hierarchy, dan field-ID collision.
   - Selection Model/Tipe/Varian menjadi field submission pertama dan tersedia bagi conditional logic.
   - Data terpercaya dari server masuk ke collection, Email/Email 2, webhook, dan `meta.product_selection`; input client yang dimanipulasi ditolak dengan 422.
   - `[all-fields]` memakai label field configurable dan `value` dataset. Template preset/custom email tetap di luar fase ini.

## Pengujian dan Acceptance

- Module discovery/order: `product_lead_form` berada setelah `form`; expected count 50 module, 48 toolbox cards, dan 100 SFC.
- Unit tests: normalization settings, 1–3 level, metadata inheritance, unique code, standalone child inference, fallback, invalid hierarchy, inactive node, dan URL sanitization.
- Runtime tests: Cards/Select, parent reset, query sync, preservation query/hash, `popstate`, media CKFinder/URL, responsive media order, dan state Normal/Hover/Selected.
- Feature tests: valid published/draft submission, dataset ownership, tampered value, cross-parent value, duplicate/ambiguous code, collect, Mail fake, webhook fake, dan conditional fields berdasarkan product selection.
- Regression: seluruh Form v2.4 lama, dataset deletion, row grid, module boundary, shared Advanced, control-binding audit, frontend runtime, dan checksum isolasi v2.3.
- Jalankan focused Node/PHP tests, full v2.4 suites, SFC compile, JS/PHP syntax, `npm.cmd run build`, dan `git diff --check`.
- Browser QA read-only pada desktop dan mobile:
  - empty configuration;
  - Cards dan Select;
  - direct `model`, `type`, dan `variant` query;
  - media kiri/kanan serta mobile stack;
  - CKFinder dan external URL;
  - detail produk, field condition, hover/selected state, DOM, layout, dan console.
- Simpan screenshot referensi, comparison, matrix, dan laporan ke `project-artifacts/qa/pagebuilder-v24-product-lead-form_<timestamp>/`.
- Jangan Save, Reset, submit form nyata, mengirim email/webhook nyata, atau Apply Dataset saat browser QA tanpa izin eksplisit; sisi tersebut diverifikasi dengan test/fake.
- Setelah source stabil, jalankan Graphify incremental dan laporkan node/edge health tanpa memasukkan backup atau artifact.

## Asumsi dan Batas Fase

- Jika beberapa Product Lead Form memakai query key yang sama pada satu halaman, selection mereka memang tersinkron; admin dapat memberi key unik per widget.
- External image/detail URL hanya menerima skema aman; CKFinder memakai rendition resolver v2.4.
