- **Zoom 12–17:** total **22.557 tile**, ukuran hasil **96,4 MB**.

Itulah penyebab utama ukurannya melonjak. Crop-nya tetap sama, tetapi area yang sama dipecah menjadi jutaan gambar yang lebih kecil cakupan geografisnya.

**OSM memengaruhi seberapa besar isi setiap tile.** Gambar yang hanya berisi satu warna mudah dikompresi menjadi PNG kecil. Gambar dengan jalan, sungai, bangunan, garis blok, dan label membutuhkan lebih banyak data. Namun, pada ekspor kita, OSM dan layer kebun **digabung menjadi satu gambar per tile**—bukan disimpan sebagai dua salinan peta terpisah.

Karena itu, **menghapus OSM bisa mengurangi ukuran, tetapi tidak menghilangkan pertumbuhan jumlah tile**. Selama area yang sama tetap diekspor penuh sampai zoom 22 dengan metode raster yang sama, jumlahnya tetap sekitar 22,7 juta tile. Angka **sekitar 30 GB** tadi merupakan **perkiraan berdasarkan sampel ekspor zoom 22**, bukan ukuran file penuh yang sudah dibuat. Sampel menghasilkan rata-rata sekitar **1,3–1,4 KB ruang file per tile**; ketika dikalikan jutaan tile, totalnya menjadi puluhan GB.

Berarti ini gimana exportnya dengan hasil vektor atau gimana dari QGIS?

---

## 2026-09-22 13:15:07 WIB — Laporan akhir assistant

**Iya, data blok, jalan, dan batas afdeling diekspor dari QGIS sebagai vektor.** Untuk bagian itu, kita tidak memakai **Generate XYZ tiles (MBTiles)** seperti sebelumnya, karena tool tersebut mengubah seluruh tampilan menjadi gambar raster.

Ada dua jalur ekspor yang bisa dipilih:

| Jalur | Ekspor dari QGIS | Cara tampil di aplikasi |
|---|---|---|
| **Layer vektor biasa** | GeoJSON, misalnya file blok, jalan, dan afdeling terpisah | Aplikasi menggambar polygon, garis, dan label dari koordinat |
| **Vector tiles** | MBTiles berisi tile vektor melalui tool ekspor vector tiles, jika tersedia pada instalasi QGIS | Aplikasi memakai pembaca vector tiles dan aturan styling |

**Untuk halaman Map Pokok kita, saya lebih menyarankan mulai dari layer vektor biasa**, karena halaman tersebut sudah memiliki kontrol untuk menampilkan jaringan jalan, zonasi blok, dan batas administrasi. Kita perlu memeriksa data yang sudah tersedia supaya tidak mengekspor dan menyimpan salinan yang sebenarnya tidak diperlukan.

Alur dari QGIS menjadi seperti ini:

1. **Pilih layer sumber**, misalnya `BUM_1` pada grup batas blok—bukan layer MBTiles hasil ekspor.
2. Klik kanan layer → **Export → Save Features As…**.
3. Pilih format **GeoJSON** dan CRS **EPSG:4326 — WGS 84** agar koordinatnya sesuai untuk peta web.
4. Simpan kolom yang diperlukan, misalnya kode blok, estate, afdeling, atau nama jalan.
5. Ulangi untuk layer jalan dan batas afdeling yang memang ingin ditampilkan.

Setelah itu, aplikasi mengatur warna isian, ketebalan garis, ukuran tulisan, dan kapan label ditampilkan. **GeoJSON membawa geometri dan atribut; styling serta posisi label QGIS tidak otomatis ikut tampil sama di browser.** Jadi, ada pekerjaan penyesuaian tampilan di aplikasi setelah ekspor.

Untuk susunan peta akhirnya:

- **Basemap:** opsional, berupa raster sampai zoom 16–17 atau basemap online.
- **Blok, jalan, afdeling, dan label:** vektor yang digambar aplikasi.
- **Zoom tampilan:** bisa sampai 20–22, sementara garis dan tulisan vektornya tetap tajam.

if [ -n "$(git status --porcelain)" ]; then

git branch "backup/vps-before-sync-$sync_stamp"

git reset --hard origin/main
