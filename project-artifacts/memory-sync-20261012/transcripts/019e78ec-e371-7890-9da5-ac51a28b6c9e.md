Hardening opsi settings widget itu tahap “penguatan” supaya fitur setting widget stabil dan aman dipakai di semua kondisi, bukan cuma “jalan” di kasus normal.

Intinya biasanya meliputi:
1. Validasi input ketat

2. Konsistensi responsive 3 view  
- Desktop/tablet/mobile tidak saling bocor nilainya, dan switching view tidak merusak state widget.

3. Sinkron editor ↔ canvas ↔ parser frontend  
- Yang terlihat di canvas sama dengan output frontend saat render.

4. Edge-case handling  
- Aman untuk undo/redo, duplicate, delete, drag-drop, save-load, nested container/grid.

5. Data migration/backward compatibility  
- Data lama tetap kebaca benar setelah schema setting baru.

6. Guard terhadap bug “silent”  
- Tidak ada setting yang hilang, reset tiba-tiba, atau berubah tanpa user sengaja.

## 2026-05-31 03:00:14 WIB — Laporan akhir assistant

Insight Anda tepat, dan ini titik desain penting sebelum lanjut.

**Kenapa sekarang bisa “merge ke column 1”**
- Logika kita saat ini memang **mengamankan agar widget tidak hilang** dengan cara rekonsiliasi ke cell pertama saat shape grid lebih kecil (mis. mobile 1 kolom).
- Akibatnya, item dari tablet col4 saat pindah ke mobile/desktop bisa terlihat “menumpuk” di cell awal.
- Jadi ini bukan random bug lagi, tapi efek dari **model data saat ini**.

**Perilaku Elementor (yang Anda tunjuk)**
- Grid Elementor cenderung **auto-flow berurutan** (isi cell 1 dulu, lalu 2, lalu 3, dst).
- Dari docs juga: grid cell hanya menampung satu elemen langsung; kalau mau banyak elemen di satu cell, biasanya pakai child container di dalam cell itu.
- Referensi: [Create a Grid container](https://elementor.com/help/create-a-grid-container/), [Grid layout options](https://elementor.com/help/grid-container-layout-options/)

**Rekomendasi saya (paling aman dan parity tinggi):**
1. Terapkan mode **Elementor-parity strict flow**  
- Hanya izinkan drop ke **first available cell** sesuai auto-flow.  
- Cell 3/4 disabled kalau cell sebelumnya belum terisi.

2. Ubah model render ke **global ordered items**, bukan snapshot per-device untuk konten  
- Konten widget tetap satu sumber (global).  
- Device hanya mengubah cara item dipetakan ke grid (jumlah cols/rows), bukan memindah ownership konten antar-view.

3. Aturan 1 cell = 1 elemen langsung (opsional tapi disarankan)  
- Jika user ingin banyak widget dalam satu cell: drop `Container` dulu di cell itu, lalu isi widget di container tersebut.

**Tradeoff**
- Kelebihan: perilaku jauh lebih stabil, cocok Elementor, bug merge/hilang berkurang drastis.
- Konsekuensi: sedikit perubahan UX dibanding implementasi Anda sekarang (yang masih mengizinkan banyak widget langsung di satu cell).

Kalau Anda setuju, saya sarankan kita ambil jalur ini:
- **Phase 1**: lock sequential drop dulu (cell gating)  
- **Phase 2**: rapikan mapping item global agar tidak merge aneh lintas device  
- **Phase 3**: migrasi kompatibilitas data lama (yang sudah multi-widget per cell)

Kalau oke, saya kerjakan dari Phase 1 dulu dengan backup penuh seperti biasa.
