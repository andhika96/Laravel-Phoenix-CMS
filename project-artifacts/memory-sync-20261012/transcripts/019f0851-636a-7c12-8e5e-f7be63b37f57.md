## 2026-06-27 16:03:25 WIB — Laporan akhir assistant

Bisa. Polanya: **semua proses Composer dan Artisan dijalankan di lokal**, lalu hasilnya di-upload ke hosting.

**Langkah aman untuk shared hosting tanpa terminal:**

1. **Siapkan project di komputer lokal**
   ```bash
   composer install --no-dev --optimize-autoloader
   npm install
   npm run build
   php artisan key:generate
   php artisan config:clear
   php artisan route:clear
   php artisan view:clear
   ```

   Jangan pakai `composer update` di hosting. Kalau butuh update package, lakukan di lokal, lalu upload ulang `vendor/`, `composer.lock`, dan file terkait.

2. **Atur `.env` untuk hosting**
   Isi sesuai database hosting:
   ```env
   APP_ENV=production
   APP_DEBUG=false
   APP_URL=https://domainkamu.com

   DB_CONNECTION=mysql
   DB_HOST=localhost
   DB_DATABASE=nama_database
   DB_USERNAME=user_database
[REDACTED_SECRET]
   ```

3. **Upload Laravel ke hosting**

   Struktur ideal:
   ```text
   /home/username/laravel-app
     app/
     bootstrap/
     config/
     database/
     resources/
     routes/
     storage/
     vendor/
     .env

   /home/username/public_html
     index.php
     build/
     .htaccess
     favicon.ico
   ```

   Jadi isi folder `public/` Laravel dipindah ke `public_html`.

4. **Edit `public_html/index.php`**

   Ubah path ini:
   ```php
   require __DIR__.'/../vendor/autoload.php';
   $app = require_once __DIR__.'/../bootstrap/app.php';
   ```

   Menjadi misalnya:
   ```php
   require __DIR__.'/../laravel-app/vendor/autoload.php';
   $app = require_once __DIR__.'/../laravel-app/bootstrap/app.php';
   ```

5. **Database**
   Karena tidak bisa `php artisan migrate`, jalankan migration di lokal dulu, lalu export database `.sql`, kemudian import lewat phpMyAdmin hosting.

   Alternatif darurat: buat route sementara untuk menjalankan migrate:
   ```php
   Route::get('/run-migrate-secret', function () {
       Artisan::call('migrate', ['--force' => true]);
       return Artisan::output();
   });
   ```

   Setelah selesai, **langsung hapus route itu**. Ini hanya untuk darurat karena berisiko keamanan.

6. **Storage link**
   Kalau butuh file upload:
   ```bash
   php artisan storage:link
   ```

   Karena hosting tidak ada terminal, bisa:
   - buat symlink dari cPanel kalau tersedia, atau
   - buat route sementara:
     ```php
     Route::get('/storage-link-secret', function () {
         Artisan::call('storage:link');
         return Artisan::output();
     });
     ```
   Lalu hapus lagi setelah berhasil.

7. **Permission**
   Pastikan folder ini writable:
   ```text
   storage/
   bootstrap/cache/
   ```

   Biasanya permission `755` atau `775`, tergantung hosting.

**Intinya:** Laravel tetap bisa jalan tanpa terminal hosting, tapi semua build dilakukan lokal. Hosting hanya menerima hasil jadi: source code, `vendor`, `.env`, hasil `npm run build`, dan database hasil import.

Misalnya struktur hosting kamu begini:

```text
/home/username/laravel-app
  app/
  bootstrap/
  config/
  storage/
  vendor/
  .env

/home/username/public_html
  index.php
  .htaccess
  build/
```

Maka `public_html/index.php` ubah jadi:

```php
<?php

use Illuminate\Http\Request;

define('LARAVEL_START', microtime(true));

// Determine if the application is in maintenance mode...
if (file_exists($maintenance = __DIR__.'/../laravel-app/storage/framework/maintenance.php')) {
    require $maintenance;

// Register the Composer autoloader...
require __DIR__.'/../laravel-app/vendor/autoload.php';

// Bootstrap Laravel and handle the request...
(require_once __DIR__.'/../laravel-app/bootstrap/app.php')
    ->handleRequest(Request::capture());
```

Yang penting bagian ini:

```php
../laravel-app/
```

harus disesuaikan dengan nama folder Laravel kamu di hosting.

Kalau folder Laravel kamu namanya misalnya `my-project`, maka jadi:

```php
require __DIR__.'/../my-project/vendor/autoload.php';

(require_once __DIR__.'/../my-project/bootstrap/app.php')
    ->handleRequest(Request::capture());
```

Kalau kamu tidak bisa taruh folder Laravel di luar `public_html`, dan terpaksa struktur seperti ini:

```text
public_html/
  index.php
  laravel-app/
    app/
    bootstrap/
    storage/
    vendor/
```

Maka path-nya jadi:

```php
if (file_exists($maintenance = __DIR__.'/laravel-app/storage/framework/maintenance.php')) {
    require $maintenance;
}

require __DIR__.'/laravel-app/vendor/autoload.php';

(require_once __DIR__.'/laravel-app/bootstrap/app.php')
    ->handleRequest(Request::capture());
```

Tapi opsi kedua kurang aman, karena folder Laravel ada di dalam `public_html`. Kalau bisa, pakai opsi pertama: folder Laravel utama di luar `public_html`, lalu `public_html` hanya berisi isi folder `public` Laravel.

## 2026-06-27 16:23:20 WIB — Laporan akhir assistant

Bisa. Kalau kamu mau tetap pakai struktur ini:

```text
public_html/
  laravel_core/
  public/
    index.php
    .htaccess
```

maka buat/edit file:

```text
public_html/.htaccess
```

isi dengan:

```apache
<IfModule mod_rewrite.c>
    RewriteEngine On

    RewriteCond %{REQUEST_URI} !^/public/
    RewriteRule ^(.*)$ public/$1 [L]
</IfModule>
```

Lalu file ini tetap harus ada:

```text
public_html/public/index.php
```

dan isi `index.php` di dalam folder `public` harus diarahkan ke `laravel_core` seperti ini:

```php
<?php

use Illuminate\Http\Request;

define('LARAVEL_START', microtime(true));

if (file_exists($maintenance = __DIR__.'/../laravel_core/storage/framework/maintenance.php')) {
    require $maintenance;
}

require __DIR__.'/../laravel_core/vendor/autoload.php';

(require_once __DIR__.'/../laravel_core/bootstrap/app.php')
    ->handleRequest(Request::capture());
```

Perhatikan bedanya: karena `index.php` berada di `public_html/public`, maka path ke `laravel_core` adalah:

```php
../laravel_core
```

bukan:

```php
laravel_core
```

Di dalam:

```text
public_html/public/.htaccess
```

pakai `.htaccess` default Laravel:

```apache
<IfModule mod_rewrite.c>
    <IfModule mod_negotiation.c>
        Options -MultiViews -Indexes
    </IfModule>

    RewriteEngine On

    RewriteCond %{HTTP:Authorization} .
    RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]

    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteRule ^ index.php [L]
</IfModule>
```

Tetap tambahkan proteksi untuk core Laravel:

```text
public_html/laravel_core/.htaccess
```

isinya:

```apache
Require all denied
```

Catatan: metode `.htaccess` redirect ke folder `public` bisa jalan, tapi yang paling rapi tetap memindahkan isi `public/` langsung ke `public_html/`. Kalau pakai cara `.htaccess`, URL tetap bisa `domain.com`, tapi secara internal diarahkan ke `public/`.

## 2026-06-27 16:47:38 WIB — Laporan akhir assistant

Errornya ini:

```text
Class "finfo" not found
vendor/league/mime-type-detection/src/FinfoMimeTypeDetector.php
```

Artinya **PHP extension `fileinfo` belum aktif di hosting**. Laravel/package `league/mime-type-detection` butuh class `finfo` untuk deteksi tipe file, biasanya saat akses storage, upload, thumbnail, media, atau file manager.

Solusinya di cPanel:

1. Masuk **cPanel**
2. Buka **Select PHP Version** / **PHP Selector** / **MultiPHP Manager**
3. Pilih versi PHP yang dipakai domain, di screenshot: `PHP 8.4.18`
4. Cari extension:

```text
fileinfo
```

5. Centang/aktifkan
6. Save / Apply
7. Refresh website

Kalau tidak ada menu `fileinfo`, coba ganti PHP ke `8.3` atau `8.2`, lalu cek lagi extension `fileinfo`. Kalau tetap tidak ada, berarti hosting perlu mengaktifkan extension itu dari server, jadi harus minta support hosting:

```text
Tolong aktifkan PHP extension fileinfo untuk domain pohonuang.id. Laravel saya error Class "finfo" not found.
```

Tambahan penting: sekarang halaman error menampilkan source code karena `APP_DEBUG=true`. Setelah testing selesai, ubah di `.env`:

```env
APP_DEBUG=false
APP_ENV=production
```

Jadi penyebabnya bukan database. Website sudah masuk Laravel, tapi berhenti saat Laravel mencoba membaca/deteksi file thumbnail/course lewat storage.

## 2026-06-27 17:08:03 WIB — Laporan akhir assistant

Itu error kode, bukan database atau `.htaccess`.

Pesannya:

```text
Class "App\Http\Controllers\Web\Account\Hash" not found
```

Artinya di controller account ada kode seperti:

```php
Hash::make($password)
```

tapi file controller itu **belum import Hash facade**, jadi PHP mengira `Hash` adalah class di namespace controller:

```php
App\Http\Controllers\Web\Account\Hash
```

Padahal yang benar adalah:

```php
Illuminate\Support\Facades\Hash
```

Edit file controller account/password kamu, kemungkinan di sekitar:

```text
app/Http/Controllers/Web/Account/
```

Di bagian atas file, tambahkan:

```php
use Illuminate\Support\Facades\Hash;
```

Contoh:

```php
<?php

namespace App\Http\Controllers\Web\Account;

use App\Http\Controllers\Controller;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Hash;
```

Lalu kode password tetap seperti ini:

```php
[REDACTED_SECRET]
```

Alternatif kalau tidak mau tambah `use`, bisa langsung tulis full path:

```php
[REDACTED_SECRET]
```

Tapi yang lebih rapi adalah tambah `use Illuminate\Support\Facades\Hash;`.

Sebelum edit di cPanel, backup dulu file controller itu. Setelah upload ulang, coba submit password lagi.
