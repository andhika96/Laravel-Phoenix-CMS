## 2026-08-19 10:58:05 WIB — Laporan akhir assistant

Baik. Planning update widget Form v2.3 kita fokuskan pada conditional logic terlebih dahulu, tanpa eksekusi.

### Tujuan

Menambahkan kemampuan:

- Pilih `B` → field tambahan muncul.
- Pilih Negara → field Provinsi muncul atau menyesuaikan kondisi.
- State bekerja di editor Canvas dan frontend publik.
- Field tersembunyi tidak ikut `required`, validasi, atau submission.
- Form lama tetap kompatibel.

### Rekomendasi scope Fase 1

Conditional logic diterapkan pada field dalam satu widget Form, bukan pada dua widget Form terpisah.

Schema yang disarankan:

```js
conditionalLogic: {
    enabled: true,
    relation: "all",
    rules: [
        {
            fieldId: "jenis",
            operator: "equals",
            value: "b"
        }
    ]
}
```

Operator awal:

- `equals`
- `not_equals`
- `contains`
- `empty`
- `not_empty`

Field tanpa `conditionalLogic` tetap selalu terlihat.

### Rencana pekerjaan

1. Kunci schema dan aturan validasi kondisi.
2. Tambahkan UI Conditional Logic di repeater `Form Fields`:
   - Enable/disable.
   - `All` atau `Any`.
   - Field sumber.
   - Operator.
   - Nilai pembanding.
3. Tambahkan evaluator reactive di Canvas.
4. Tambahkan evaluator frontend pada [`frontend-runtime.js`](/D:/Laragon/www/laravel-13-phoenix/public/js/pagebuilder_elementor_v23/frontend-runtime.js:911).
5. Update Blade renderer agar kondisi dan state awal konsisten.
6. Update server validation di [`FormSubmissionHandler.php`](/D:/Laragon/www/laravel-13-phoenix/app/Support/PageBuilderElementorV23/FormSubmissionHandler.php:135).
7. Tambahkan test normalization, Canvas, frontend runtime, Blade, dan server validation.
8. Browser QA read-only tanpa Save/Reset.

### Keputusan UX yang perlu dikunci

Rekomendasi saya: ketika field disembunyikan, field tersebut di-`disable`, nilainya dikosongkan, dan tidak dikirim. Ini mencegah nilai lama ikut tersimpan tanpa terlihat.

Dependent select Negara → Provinsi kita jadikan Fase 2 setelah conditional visibility stabil. Fase tersebut membutuhkan schema mapping options tersendiri.

File yang kemungkinan disentuh nanti:

- `definition.js`
- `Settings.vue`

- `render_pro_widget.blade.php`
- `FormSubmissionHandler.php`
- test Node dan PHPUnit terkait Form

Arti field:

### Dua mode pengelolaan

**Visual Manager**

Untuk data kecil:

- Add Root Item.
- Add Child Item.
- Edit `label`, `name`, `code`, `value`, `kind`.
- Pilih `parentId`.
- Atur urutan dan status aktif.
- Delete atau pindahkan node.

Contohnya Variant 5 dapat dibuat lewat form, lalu ditambahkan 2–5 Subvariant di bawahnya.

**JSON Manager**

Untuk data besar:

- Paste atau import JSON melalui modal.
- Validate struktur.
- Tampilkan jumlah node, root, kedalaman, dan error.
- Preview hierarchy.
- Export kembali ke JSON.
- Simpan sebagai dataset reusable.

Kedua mode tersebut harus menggunakan normalizer dan validator yang sama agar hasilnya konsisten.

### Arsitektur pemakaian

```text
Dataset Manager
        ↓
Dataset tersimpan terpusat
        ↓
Widget Form memilih datasetId
        ↓
Field Parent → Field Child → Field Grandchild
```

Tiga widget di tiga halaman dapat memakai dataset yang sama tanpa menyalin JSON ke setiap page. Jika dataset diubah, sistem perlu memberi peringatan bahwa perubahan dapat memengaruhi semua widget yang menggunakannya.

Hal yang masih perlu dikunci sebelum planning final:

- JSON import mengganti seluruh dataset atau merge/upsert ke dataset lama.
- Penyimpanan dataset memakai JSON payload atau node database terpisah.
- Nilai submission memakai `id`, `code`, atau `value`.
- Apakah dataset dapat diedit oleh semua user atau hanya admin.
- Apakah API hanya untuk import/sync, bukan runtime.
