**Base path yang saya usulkan:**

```text
/api/v1/agronomy
```

Semua path di bawah mengikuti base path tersebut. `GET, POST` berarti dua operasi pada path yang sama. Daftar lengkapnya memuat **65 baris route dengan 84 operasi HTTP**, yang dibuat bertahap.

|---|---|---|

| GET | `/units` | Unit dan implement yang cocok untuk Emdek/Sprayer |
| GET, POST | `/activity-types` | Daftar dan pembuatan kode kegiatan agronomi |
| PATCH | `/activity-types/{id}` | Perubahan metadata atau penonaktifan kegiatan |

Login tetap menggunakan akun dan autentikasi BUM yang tersedia. Data pegawai, lokasi, dan kendaraan memakai master yang sesuai di CMS.

**Pejabat approval RKB/RKH harus ditetapkan terlebih dahulu.** Materi belum cukup untuk menetapkan Admin CMS atau Estate Manager sebagai approver kedua dokumen tersebut.

| POST | `/work-sessions/{id}/close` | Menutup sesi dengan HM akhir, waktu, kendala, dan rekonsiliasi bahan |
| GET, POST | `/work-results` | Melihat daftar dan membuat LHO/hasil kerja MKTI maupun Go Blok |
| GET, PATCH | `/work-results/{id}` | Melihat detail dan mengubah draft hasil kerja |
| POST | `/work-results/{id}/trips` | Menambahkan rit Emdek/Sprayer beserta volume, pokok, jelajah, dan waktu |
| PATCH | `/work-trips/{id}` | Melengkapi waktu mulai/selesai atau mengoreksi draft rit |
| PUT | `/work-results/{id}/worker-allocations` | Menetapkan pembagian hasil per pekerja dan peran |
| POST | `/work-results/{id}/submit` | Menyerahkan hasil kerja, rincian rit, alokasi kru, dan bukti |
| POST | `/work-results/{id}/inspections` | Memverifikasi atau mengembalikan hasil, termasuk jumlah yang diterima |
| POST | `/work-results/{id}/corrections` | Membuat revisi koreksi hasil yang telah dikirim |
| GET, POST | `/workday-closings` | Melihat daftar dan melakukan penutupan hari kerja setelah rekonsiliasi |

Perbedaan pencatatan ketiga jenis pekerjaan:

| Jenis pekerjaan | Data hasil utama |
|---|---|
| **Emdek** | Kg pupuk, jumlah pokok, dosis aktual, rit, jelajah, waktu, HM, material, dan kontribusi kru |
| **Mounted Sprayer** | Ha hasil semprot, pokok pendukung, rit, jelajah, waktu, HM, material, dan kontribusi kru |
| **Go Blok manual** | Jenis kegiatan, volume hasil, satuan, blok, pekerja, interval waktu, material, dan bukti |

Hasil fisik unit dihitung sekali. Pembagian hasil kepada Aplikator atau Pemuat menjadi data kontribusi pekerja, sehingga jumlah hasil unit tidak berlipat karena dicatat oleh beberapa orang.

**7. Foto dan dokumen bukti**

| Metode | Endpoint | Fungsi |
|---|---|---|

Bukti dapat dikaitkan dengan peta, pemeriksaan unit, rit, hasil kerja, atau transaksi yang sesuai. Submit hasil memeriksa kelengkapan bukti yang diwajibkan.

**8. Laporan dan export**

| Metode | Endpoint | Fungsi |
|---|---|---|
| GET | `/reports/emdek` | Laporan Emdek: rencana/realisasi kg, pokok, dosis, rit, produktivitas, HM, dan biaya |
| GET | `/reports/sprayer` | Laporan Sprayer: rencana/realisasi ha, pokok, rit, produktivitas, HM, dan biaya |
| GET | `/reports/go-blok` | Laporan Go Blok per kegiatan, satuan, pegawai, waktu, hasil, dan biaya |

**9. Sinkronisasi offline dan audit**

| Metode | Endpoint | Fungsi |
|---|---|---|
| GET | `/sync/changes` | Mengambil perubahan data sejak cursor server, termasuk revisi dan pembatalan |
| POST | `/sync/submissions` | Mengirim batch pencatatan offline dengan hasil penerimaan atau konflik per item |
| GET | `/audit-events` | Melihat riwayat perubahan, aktor, keputusan, dan koreksi sesuai kewenangan |

Pencatatan lapangan memakai identitas submission agar retry tidak menggandakan data. Approval, posting stok, verifikasi final, dan release payroll dilakukan online.

**10. Aturan upah dan simulasi pendapatan**

| Metode | Endpoint | Fungsi |

Kelompok ini masuk setelah rumus upah disepakati. Preview menyimpan aturan yang digunakan dan tidak memposting hak upah ke payroll final.

**11. Payroll final**

| Metode | Endpoint | Fungsi |
|---|---|---|
| GET, POST | `/payroll-batches` | Melihat daftar dan membuat draft rekap payroll per periode/scope |
| GET | `/payroll-batches/{id}` | Melihat rincian pekerja, komponen upah, dan rekonsiliasi |
| POST | `/payroll-batches/{id}/decisions` | Mencatat verifikasi/persetujuan sesuai urutan otorisasi |
| POST | `/payroll-batches/{id}/release` | Mengunci batch yang telah disetujui untuk penghubung ke sistem payroll resmi |

Release membutuhkan aturan aktif, hasil terverifikasi, kehadiran yang diakui, dan pemeriksaan agar komponen upah tidak tercatat dua kali pada modul berbeda.

**Urutan implementasi yang direncanakan**

| Tahap | API yang dibuat |
|---|---|
| **A — Fondasi dan rencana** | Akses pengguna, referensi, kegiatan, RKB, PBLK, RKH, dan penugasan |
| **B — Bahan dan kesiapan** | SPMB, transaksi bahan, absensi, P2H/PM10, kesiapan unit, dan pengisian solar |
| **C — Pelaksanaan dan pemeriksaan** | Sesi kerja, hasil MKTI/Go Blok, rit, alokasi pekerja, bukti, inspeksi, PBLH, dan closing |
| **D — Pelaporan dan sinkronisasi** | Laporan, export, batch/delta offline, dan akses audit |
| **E — Simulasi upah** | Versi aturan upah dan preview setelah rumus disepakati |
| **F — Payroll final** | Batch, verifikasi/persetujuan, dan release setelah SOP penggajian jelas |

Kontrol akses, pencatatan audit, pencegahan submission ganda, dan kontrol versi dibangun sejak tahap awal serta digunakan oleh endpoint berikutnya.
