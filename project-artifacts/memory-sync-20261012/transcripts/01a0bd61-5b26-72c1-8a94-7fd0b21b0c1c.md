Bisa untuk keduanya—**bukan khusus React**.

`design-taste-frontend` adalah *agent skill* berisi arahan desain dan implementasi frontend, bukan package React atau library komponen. Ia tidak menambah dependency ke aplikasi. Karena itu ia dapat dipakai pada:

- React, Next.js, Vue, Nuxt, Svelte, Angular
- Laravel Blade, Livewire, Inertia, dan aplikasi PHP biasa
- **Bootstrap 5** — memakai grid, utility class, dan komponen Bootstrap yang sudah tersedia
- **Tailwind CSS** — menghasilkan/menata utility class Tailwind
- UI kit seperti shadcn/ui, Flowbite, DaisyUI, AdminLTE, CoreUI, Metronic, atau komponen internal proyek
- CSS/SCSS biasa

Untuk proyek Laravel CMS yang menggunakan Bootstrap 5 atau UI kit, Taste Skill justru sebaiknya diberi batasan eksplisit seperti ini:

> Gunakan design-taste-frontend untuk hierarchy, spacing, typography, dan layout. Pertahankan Bootstrap 5 serta UI kit yang sudah ada; jangan menambah dependency, jangan mengganti design token global, dan gunakan komponen/utility yang tersedia sebelum membuat CSS baru.

Artinya, Taste Skill membantu menghindari UI generik dan memperbaiki *visual hierarchy*, tetapi **tetap menggunakan fondasi teknis yang sudah ada**—misalnya `container`, `row`, `col-*`, `btn`, `card`, modal Bootstrap, atau class Tailwind/UI kit yang telah dipakai proyek.

Untuk pekerjaan UI kita, pembagiannya paling aman:

- **Taste Skill**: arah visual, komposisi, typography, spacing, density, dan motion.
- **UI UX Pro Max**: usability, accessibility, responsive behavior, design-system consistency, serta QA implementasi.
- **Ponytail**: menjaga agar hasilnya tidak menambah framework, UI kit, atau abstraction baru bila Bootstrap/Tailwind/komponen yang ada sudah cukup.

Repositori tersebut juga menyatakan skill-nya framework-agnostic dan menargetkan *design intent*, bukan API framework tertentu. [Taste Skill README](https://github.com/Leonxlnx/taste-skill)

Yang perlu diubah secara desain:

1. **Pisahkan aksi berdasarkan prioritas, bukan semua tombol sederajat.**

   - Primary CTA: **Tambah Data**
   - Aksi pencarian: **Saring (0)**
   - Aksi operasional: **Import ZIP**, **Riwayat Import**, **Tampilkan Map**
   - Aksi berisiko/destruktif: **Hapus**
   - Aksi khusus: **Penyesuaian Lokasi**

   Di desktop, `Import ZIP`, `Riwayat Import`, dan `Tampilkan Map` masih dapat ditampilkan langsung. Sementara `Hapus` dan `Penyesuaian Lokasi` sebaiknya masuk ke tombol dropdown **Tindakan lainnya**. Ini menghilangkan baris kedua yang “tidak sengaja” tanpa menyembunyikan kemampuan pengguna.

2. **Pertahankan dua kolom hanya pada layar lebar.**

   Kolom judul/breadcrumb kiri dapat diberi lebar stabil sekitar `280–320px`, sedangkan sisi kanan memakai sisa ruang yang fleksibel. Kuncinya adalah `minmax(0, 1fr)` pada kolom kanan agar input tidak memaksa lebar card dan menimbulkan overflow.

3. **Form pencarian tetap dua kolom pada desktop, satu kolom pada mobile.**

   - Desktop: dropdown “Cari berdasarkan” lebih sempit, misalnya 35–40%; input keyword mengambil sisanya.
   - Mobile: label → field pertama → label → field kedua, semuanya `width: 100%`.
   - Catatan pencarian berada tepat di bawah kedua field, bukan di antara tombol.

4. **Pada mobile, hanya tampilkan dua tombol yang paling sering dipakai.**

   - `Tambah Data` sebagai tombol primary penuh selebar container.
   - `Saring (0)` sebagai tombol secondary penuh selebar container atau satu baris dengan `Tindakan lainnya`, tergantung tingkat kepentingannya.
   - Sisanya ada dalam dropdown/offcanvas. Ini mencegah enam tombol kecil, sulit disentuh, dan membuat halaman lebih tenang.

5. **Jangan hanya mengandalkan `flex-wrap`.**

   `flex-wrap` cocok sebagai fallback, tetapi bukan solusi struktur. Saat tombol membungkus secara otomatis, urutan dan pengelompokan menjadi tidak terkontrol, seperti kondisi pada screenshot sekarang. Gunakan layout toolbar yang eksplisit: grup tombol utama + dropdown untuk aksi sekunder.

Jika halaman ini memakai Bootstrap 5, struktur responsif dasarnya dapat diarahkan seperti berikut:

```html
<div class="master-toolbar">
  <section class="master-toolbar__identity">
    <!-- Judul + breadcrumb -->
  </section>

  <section class="master-toolbar__controls">
    <div class="row g-2">
      <div class="col-12 col-md-4">
        <!-- Label + select Cari berdasarkan -->
      </div>
      <div class="col-12 col-md-8">
        <!-- Label + input Kata pencarian -->
      </div>
    </div>

    <p class="form-text mb-2">
      Mencari awalan teks pada semua kolom; tahun tanam harus cocok persis.
    </p>

    <div class="d-flex flex-wrap gap-2 align-items-center">
      <!-- Import ZIP, Riwayat Import, Map -->
      <!-- Saring -->
      <!-- Tambah Data -->
      <!-- Dropdown Tindakan lainnya -->
    </div>
  </section>
</div>
```

```css
.master-toolbar {
  display: grid;
  grid-template-columns: minmax(280px, 0.32fr) minmax(0, 0.68fr);
  gap: 24px;
  align-items: start;
}
```

```bash
git rev-parse HEAD > "$recovery_dir/head-before.txt" &&
git diff --binary > "$recovery_dir/working-tree.patch" &&

  ':!:project-artifacts/**' > "$recovery_dir/files-before.list" &&
tar --null -T "$recovery_dir/files-before.list" \
  -czf "$recovery_dir/files-before.tar.gz" &&
tar -czf "$recovery_dir/git-metadata-before.tar.gz" .git &&
tar -tzf "$recovery_dir/files-before.tar.gz" >/dev/null &&
tar -tzf "$recovery_dir/git-metadata-before.tar.gz" >/dev/null &&
printf 'Backup terverifikasi: %s\n' "$recovery_dir"
```
