## 2026-09-15 10:20:00 WIB — Laporan akhir assistant

**Saya menemukan jalur komputasi yang sangat berat di frontend GOKUT, disertai request dashboard ganda dan kesalahan filter sopir di backend.** Namun, browser macet dan pesan **“Data route not found” perlu dibedakan**—keduanya tidak selalu berasal dari proses yang sama.

Source aplikasi belum saya ubah; pekerjaan ini khusus pemeriksaan dan trace.

## 1. Kandidat utama browser macet: pencocokan setiap titik GPS ke seluruh jaringan jalan

Saat memilih **Angkut TBS**, alurnya:

1. Ambil jaringan jalan berdasarkan estate sopir.
2. Ambil koordinat perjalanan.
3. Cocokkan **setiap titik GPS dengan seluruh fitur jalan** menggunakan Turf.
4. Gambar hasilnya di Leaflet.

Langkah ketiga berjalan **sinkron di thread utama browser**, tempat browser juga menangani klik dan menggambar tampilan. Selama komputasi berlangsung, halaman dapat terasa berhenti.

Lokasinya di [fungsi snapTripRouteToRoads](/D:/Laragon/www/laravel-13-cms-bum/public/assets/js/vuejs-v3-2024-dashboard.js:7124).

**Bukti benchmark fungsi asli menggunakan jaringan jalan BUM 1 dari database lokal:**

| Titik GPS | Fitur jalan | Pemanggilan pencarian titik terdekat | Waktu |
|---|---:|---:|---:|
| 10 titik | 1.255 | 12.550 kali | 0,64 detik |
| 100 titik | 1.255 | 125.500 kali | **7,70 detik** |

Bahkan pada pengujian tersebut, **semua titik GPS sama**, tetapi pencarian tetap diulang. Batas snapping **200 meter** baru diperiksa setelah pencarian seluruh jalan selesai, sehingga tidak mengurangi pekerjaan pencarian.

**Status bukti:** beban fungsi sudah terverifikasi lewat eksekusi Node lokal. Ini belum merupakan pengukuran waktu Firefox atau rekaman perjalanan dari screenshot.

## 2. Ada pemanggilan dashboard ganda

Pada pembukaan tab GOKUT:

- `listDataTabGokut(false)` mengambil daftar sopir dan mulai memuat data dashboard.
- Respons daftar sopir mengubah `unitDtTrip`.
- Watcher atas `unitDtTrip` kembali menjalankan `listDataTabGokut(false, true)`.

Akibatnya, **dua rangkaian pemuatan dashboard dapat berjalan bersamaan**, masing-masing berisi 14 request yang dijalankan secara berurutan.

Ini sesuai dengan pola pada screenshot kedua: endpoint muncul berpasangan, sebagian tanpa parameter dan sebagian dengan `?emp_name=&date=`.

Referensi: [watcher pemicu refresh](/D:/Laragon/www/laravel-13-cms-bum/public/assets/js/vuejs-v3-2024-dashboard.js:476) dan [rangkaian request GOKUT](/D:/Laragon/www/laravel-13-cms-bum/public/assets/js/vuejs-v3-2024-dashboard.js:4539).

**Status bukti:** alur ganda terkonfirmasi dari source; jumlah request aktual belum diukur melalui capture browser langsung.

## 3. Angka Duration dan Distance belum benar-benar memfilter sopir

Ini menjelaskan mengapa **Duration/Distance bisa berisi angka, tetapi route tidak ditemukan**.

Backend membatasi nama sopir hanya pada relasi `driver`. Query induk tetap mengambil aktivitas semua sopir pada tanggal pilihan, lalu menjumlahkan item aktivitas tersebut.

Jadi **2015 KM pada screenshot belum bisa dianggap sebagai jarak perjalanan YOHANES YOPI**. Source saat ini memungkinkan angka itu merupakan agregasi aktivitas sopir lain pada tanggal tersebut.

Masalah serupa terdapat pada endpoint route: lokasi GPS semua aktivitas yang cocok tanggal dan kegiatan ikut diambil, kemudian aktivitas sopir lain baru dilewati dalam loop PHP. Ini menambah pengambilan data yang tidak diperlukan.

Referensi: [Duration dan Distance](/D:/Laragon/www/laravel-13-cms-bum/app/Http/Controllers/Web/Dashboard/Dashboard_GOKUTController.php:93), [query route](/D:/Laragon/www/laravel-13-cms-bum/app/Http/Controllers/Web/Dashboard/Dashboard_GOKUTController.php:167).

## 4. “Data route not found” memang terjadi pada database lokal yang saya periksa

Hasil pemeriksaan database **loopback/localhost yang dikonfigurasi checkout ini**, memakai transaksi read-only:

| Pemeriksaan | Hasil |
|---|---|
| Tanggal aktivitas terbaru | **29 Agustus 2026** |
| Aktivitas TBS tanggal 14 September 2026 | **0** |
| Response controller route untuk pilihan pada screenshot | `failed`, 68 byte |
| Waktu controller | Sekitar **25 ms** |
| Aktivitas TBS terakhir YOHANES YOPI | 24 Agustus 2026 |
| Lokasi GPS untuk aktivitas terakhir tersebut | **0** |

Artinya, untuk database lokal ini, pesan tersebut berasal dari **ketiadaan data route**.

**Batas penting:** kedua screenshot menampilkan `itbumdev.web.id`. Saya belum membuktikan bahwa database yang dipakai halaman browser tersebut sama dengan database lokal checkout ini. Firefox juga tidak tersedia melalui koneksi browser sesi ini.

Selain itu, **response route berstatus `failed` melewati proses snapping**. Jadi saya belum menyimpulkan bahwa snapping adalah penyebab tunggal warning Firefox yang muncul bersamaan dengan toast tersebut; pekerjaan lain atau request sebelumnya perlu dilihat melalui profil browser.

## 5. Layer route lama juga tidak dibuang

Saat route berhasil dimuat kembali, kode membuat layer baru dan menambahkannya ke peta. Referensi sebelumnya ditimpa tanpa menghapus layer lama. Penggunaan berulang dapat menumpuk layer. Peta juga difokuskan ulang untuk setiap feature.

Referensi: [pembuatan layer route](/D:/Laragon/www/laravel-13-cms-bum/public/assets/js/vuejs-v3-2024-dashboard.js:5483).

## Prioritas perbaikan berdasarkan trace

1. **Kurangi komputasi snapping:** persempit kandidat jalan secara spasial, hindari penghitungan ulang titik identik, dan pindahkan pekerjaan berat dari thread utama jika snapping tetap diperlukan.
2. **Filter sopir pada query induk** route, Duration, dan Distance.
3. **Hilangkan pemuatan dashboard ganda** serta cegah respons lama menimpa pilihan terbaru.
4. **Ganti layer route sebelumnya** dan fokuskan peta sekali setelah seluruh route selesai dimuat.
