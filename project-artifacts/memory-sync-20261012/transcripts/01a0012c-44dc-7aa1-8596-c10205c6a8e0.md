# Plan Revisi: Hero Slider dengan Image dan Video

## Ringkasan

Hero Slider menjadi media slider yang dapat mencampur slide image dan video. Runtime slider tetap native v2.3, tetapi provider video memakai adapter resmi yang di-load secara lazy. Splide Video memang memakai lifecycle `play`, `pause`, dan `ended` untuk HTML video, YouTube, dan Vimeo; Dailymotion juga menyediakan API event dan kontrol serupa. [Splide Video](https://splidejs.com/extensions/video/) [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference) [Vimeo Player SDK](https://developer.vimeo.com/player/sdk/reference) [Dailymotion Web SDK](https://developers.dailymotion.com/docs/listen-to-player-events-web)

## Kontrak media per slide

Setiap slide memilih satu media utama:

- `image`
- `video`

Video mendukung:

- Video lokal/CKFinder.
- Direct URL HTML5 seperti MP4, WebM, atau OGG.
- YouTube.
- Vimeo.
- Dailymotion.
- Provider lain melalui generic embed fallback.

Setiap video memiliki:

- URL atau provider ID.
- Poster/cover image responsive.
- Aspect ratio fallback, default `16:9`.
- Autoplay `inherit`, `on`, atau `off`.
- Loop video.
- Custom Play/Pause.
- Custom Mute/Unmute.
- Resume posisi ketika kembali ke slide.
- Adapter status `ready`, `playing`, `paused`, `ended`, dan `error`.

Provider yang tidak dikenal tetap dapat ditampilkan, tetapi memakai interval slider biasa dan tidak dijanjikan mendukung custom control atau mode durasi.

## Kontrak autoplay dan lifecycle

Slider autoplay dan video autoplay menjadi dua setting terpisah.

| Kondisi | Perilaku |
|---|---|
| Slide tidak aktif | Video langsung pause dan current time dipertahankan |
| Slide aktif + video autoplay On | Video aktif mencoba play secara muted |
| Mode interval | Slider menunggu interval, lalu pause video dan pindah slide |
| Mode video duration + video berhasil play | Menunggu event `ended`, pause, lalu pindah slide |
| Tidak ada video, autoplay Off, provider gagal, atau SDK gagal | Fallback ke interval slider |
| Kembali ke slide video | Video resume dari posisi sebelumnya |
| Slider autoplay Off | Tidak ada perpindahan otomatis; video tetap dapat dimainkan manual |

Mode durasi akan memiliki pilihan:

- `Fixed interval`
- `Follow video duration`

Autoplay bersuara tidak dapat dijamin oleh browser. Karena itu autoplay video akan memakai `muted` dan `playsinline`; tombol Unmute tetap tersedia setelah interaksi pengguna. [MDN Autoplay](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

## Pengaturan widget

Selain seluruh pengaturan Hero Slider sebelumnya, tambahkan:

- Global Video Autoplay: On/Off.
- Video Duration Mode: interval atau mengikuti durasi.
- Video autoplay fallback.
- Video muted autoplay.
- Video controls: custom minimal.
- Video loop.
- Poster image per video.
- Video aspect ratio.
- Adaptive Height atau Fixed Height.
- Minimum height responsive.
- Provider privacy/iframe permissions.
- Loading state dan fallback jika provider SDK gagal.

Mode Adaptive Height:

- Image mengikuti ukuran media aktif.
- Native video mengikuti metadata video.
- YouTube/Vimeo/Dailymotion memakai aspect ratio fallback sampai metadata tersedia.
- Minimum height responsive tetap berlaku agar layout tidak collapse.
- Perubahan tinggi dianimasikan secara halus.

Kontrol custom digunakan untuk provider yang memiliki adapter penuh. Provider fallback dapat menampilkan kontrol bawaan provider karena kontrol custom tidak dapat dijamin bekerja pada iframe asing.

## Implementasi teknis

- Tambahkan node type `hero_slider` sebagai widget Pro dedicated.
- Tambahkan definition/normalizer, Settings, Canvas, Blade renderer, dan test khusus Hero Slider.
- Pertahankan `Hero Banner`, `Slides`, dan `Media Carousel` existing tanpa perubahan kontrak.
- Tambahkan controller `initHeroSlider` dan `VideoController` pada runtime v2.3.
- Lazy-load SDK hanya ketika provider terkait digunakan:
  - YouTube IFrame API.
  - Vimeo Player SDK.
  - Dailymotion Web SDK.
- Direct HTML5 video tidak membutuhkan SDK eksternal.
- Jika SDK atau provider gagal dimuat, runtime tidak error fatal dan otomatis kembali ke interval slider.
- Video yang tidak aktif tidak diberi kesempatan playback; iframe/video dapat ditunda atau dihentikan sesuai adapter.
- Arah horizontal/vertical tetap dapat berbeda untuk Desktop, Tablet, dan Mobile.
- Pagination mengikuti direction: dots horizontal di bawah dan rail vertical untuk mode vertical.
- Keyboard, drag, mouse wheel, reduced motion, lazy-load, arrows, pagination, loop, rewind, fade, dan progress bar tetap mengikuti plan Hero Slider sebelumnya.

## 2026-08-15 23:15:32 WIB — Laporan akhir assistant

Ya, ini kemungkinan besar masalah jalur scheduler yang berbeda antara Firefox dan Chrome, bukan error Video Playlist lagi.

Penyebab utama di source aktif:

1. `warmWidgetModules()` langsung memuat Canvas dan Settings saat `pointerdown`. Di Firefox, proses compile SFC dapat masih berjalan ketika Anda mulai mengetik.

2. Setelah gesture pertama, `scheduleWidgetSettingsPreloadAfterFirstGesture()` masih melakukan preload shared controls melalui `requestIdleCallback()`.

3. Guard input hanya mengandalkan:

```js
navigator.scheduling?.isInputPending?.(...)
```

Firefox umumnya tidak menyediakan API ini, sehingga hasil optional chaining menjadi `undefined` dan dianggap tidak ada input aktif. Akibatnya preload tetap berjalan ketika Anda sedang mengetik. API tersebut memang masih eksperimental/deprecated dan tidak boleh menjadi satu-satunya pengaman scheduling. [MDN isInputPending](https://developer.mozilla.org/en-US/docs/Web/API/Scheduling/isInputPending)

`requestIdleCallback()` juga tetap menjalankan pekerjaan di main thread; pekerjaan compile SFC yang berat bisa memblokir input. [MDN requestIdleCallback](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestIdleCallback)

Selain itu, deep watcher `rootNodes` masih melakukan traversal layout setiap perubahan setting di [app.js](D:/Laragon/www/laravel-13-phoenix/public/js/pagebuilder_elementor_v23/app.js:3928). Debounce sebelumnya hanya menunda `JSON.stringify`, bukan menghilangkan traversal Vue.

Jadi Chrome terasa aman karena scheduler dan engine JavaScript-nya lebih cepat, sedangkan Firefox memperlihatkan beban preload/compile tersebut.

Solusi paling tepat berikutnya adalah menghapus preload shared controls setelah gesture pertama, lalu memakai fallback scheduler berbasis aktivitas pointer/keyboard yang berlaku sama di semua browser. Saya belum mengubah source pada turn ini karena Anda sedang menanyakan penyebabnya terlebih dahulu.
