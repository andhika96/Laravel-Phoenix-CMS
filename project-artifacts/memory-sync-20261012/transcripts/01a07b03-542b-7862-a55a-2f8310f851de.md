## 2026-09-07 15:53:41 WIB — Laporan akhir assistant

Masalahnya bukan lagi `connection timed out`. HeidiSQL sudah berhasil tersambung ke database, tetapi gagal ketika memasukkan data spasial ke kolom `GEOMETRY`.

Akar masalah yang terlihat dari dump:

- File dump sebenarnya berukuran sekitar **558 MB**.
- Header dump dibuat dari **MySQL 8.0.46**.
- Tabel yang gagal adalah kemungkinan besar:

  ```sql
  lr_roads.geometry
  ```

- Pada dump, kolom tersebut didefinisikan sebagai:

  ```sql
  `geometry` geometry DEFAULT NULL
  ```

  pada sekitar baris 3664.

- Data geometry dimasukkan sebagai binary internal:

  ```sql
  _binary '...'
  ```

- Ada tepat **12.855 nilai geometry** pada tiga statement `INSERT` besar di sekitar baris 3677–3679.
- File SQL project yang ada di [lr_roads.sql](D:/Laragon/www/laravel-11-cms-bum/database/data/sql/lr_roads.sql) memakai representasi seperti:

  ```sql
  0xe610000001050000...
  ```

  Prefix `e6100000` adalah SRID `4326`, lalu diikuti data WKB.

MySQL 8 menyimpan geometry sebagai **4 byte SRID + WKB**. Dokumentasi MySQL menjelaskan bahwa geometry internal memang diawali 4 byte SRID sebelum WKB. [MySQL 8.0 Spatial Type Storage](https://dev.mysql.com/doc/refman/8.0/en/storage-requirements.html)

Sementara format WKB yang dijelaskan MariaDB dimulai dari byte order dan tipe geometry, bukan dari prefix SRID MySQL tersebut. [MariaDB WKB Format](https://mariadb.com/docs/server/reference/sql-statements/geometry-constructors/wkb/well-known-binary-wkb-format)

Jadi diagnosis paling kuat adalah:

> Dump dibuat dari MySQL 8, tetapi sedang dimasukkan ke MariaDB/XAMPP yang format internal geometry-nya tidak kompatibel dengan binary geometry MySQL 8.

Karena MariaDB membaca binary tersebut sebagai WKB biasa, byte awalnya dianggap tidak valid sebagai geometry. Akibatnya muncul:

```text
SQL Error (1416):
Cannot get geometry object from data you send to the GEOMETRY field
```

### Kenapa phpMyAdmin sebelumnya timeout?

Itu masalah berbeda. File dump berukuran sekitar 558 MB, sehingga proses melalui phpMyAdmin dapat terkena batas:

- `upload_max_filesize`;
- `post_max_size`;
- `max_execution_time`;
- timeout Apache/PHP;
- timeout browser;
- `max_allowed_packet`.

Jadi:

- phpMyAdmin gagal di tahap upload/request yang panjang;
- HeidiSQL berhasil melewati koneksi dan mulai menjalankan SQL;
- HeidiSQL kemudian berhenti di data `lr_roads.geometry`.

### Jangan matikan “Stop on errors in batch mode”

Kalau opsi tersebut dimatikan, proses mungkin terlihat selesai, tetapi sekitar **12.855 geometry jalan** bisa dilewati atau gagal diam-diam. Database memang terisi sebagian, tetapi data jalan/spatial menjadi tidak lengkap.

### Cek versi database tujuan

Jalankan ini di HeidiSQL pada koneksi XAMPP:

```sql
SELECT
    VERSION() AS db_version,
    @@version_comment AS db_comment;
```

Jika hasilnya mengandung:

```text
MariaDB
```

maka dugaan incompatibility tersebut terkonfirmasi.

### Solusi paling aman

Gunakan server tujuan dengan keluarga database yang sama, yaitu **MySQL 8.0 atau MySQL 8.4**, lalu import dump memakai client command-line atau HeidiSQL.

Contoh dari Command Prompt:

```bat
mysql.exe --max_allowed_packet=1G -u root -p bum_db < "C:\Users\aruna\Downloads\dump-bum_db-202609071153.sql"
```

Gunakan `mysql.exe` dari instalasi MySQL 8 tujuan. Pada komputer ini yang terdeteksi adalah:

```text
D:\Laragon\bin\mysql\mysql-8.4.5-winx64\bin\mysql.exe
```

Contoh lengkap:

```bat
"D:\Laragon\bin\mysql\mysql-8.4.5-winx64\bin\mysql.exe" --max_allowed_packet=1G -u root -p bum_db < "C:\Users\aruna\Downloads\dump-bum_db-202609071153.sql"
```

Pastikan database tujuan sudah dibuat terlebih dahulu:

```sql
CREATE DATABASE bum_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

### Kalau wajib tetap menggunakan MariaDB XAMPP

Dump harus dikonversi terlebih dahulu. Jangan sekadar menghapus kata `_binary`, karena data geometry-nya tetap memakai format internal MySQL 8.

Pilihan yang benar:

1. Export ulang dari server MySQL sumber menggunakan WKB portable.
2. Impor WKB dengan `ST_GeomFromWKB(...)` atau fungsi geometry MariaDB.
3. Atau konversi data `lr_roads.geometry` secara khusus sebelum import.
4. Tabel non-spatial dapat diimpor terpisah, lalu `lr_roads` dikonversi belakangan.

Secara konsep, data yang harus dimasukkan ke MariaDB adalah seperti:

```sql
ST_GeomFromWKB(0x0105000000..., 4326)
```

bukan langsung binary internal MySQL 8:

```sql
_binary '...'
```

Dokumentasi MySQL juga menyarankan konversi geometry ke WKB atau WKT ketika data perlu dipindahkan antar sistem. [MySQL Fetching Spatial Data](https://dev.mysql.com/doc/refman/8.0/en/fetching-spatial-data.html) dan [MySQL Populating Spatial Columns](https://dev.mysql.com/doc/refman/8.0/en/populating-spatial-columns.html)
