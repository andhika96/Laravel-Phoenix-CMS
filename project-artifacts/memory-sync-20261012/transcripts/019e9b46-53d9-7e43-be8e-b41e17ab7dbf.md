Lihat [app.js](/D:/Laragon/www/laravel-13-phoenix/public/js/pagebuilder_elementor/app.js:927) dan CSS [pagebuilder_elementor.css](/D:/Laragon/www/laravel-13-phoenix/public/assets/css/pagebuilder_elementor.css:413).

Jadi prinsip yang harus kita pegang untuk parity dengan demo Elementor adalah:

1. **Yang harus sama persis dengan frontend adalah content box model-nya**  
   Artinya `padding`, `margin`, `gap`, `min-height`, `grid/flex behavior`, alignment, width, dan background.

2. **Editor chrome boleh berbeda, tapi harus out-of-flow**  
   Toolbar, label node, placeholder kolom, dan tombol aksi harus dibuat `absolute/floating`, jangan ikut nambah tinggi, padding, atau flow konten.

3. **Kalau toolbar model-nya “Inset Strip” masuk ke dalam node dan makan ruang atas, itu berisiko merusak parity**  
   Jadi dari 3 prototype tadi:
   - `Split Capsules` paling aman
   - `Sidecar Rail` juga aman
   - `Inset Strip` paling berisiko kalau targetmu adalah canvas sangat dekat ke frontend parser

Kalau targetmu memang **seperti Elementor**, rekomendasi saya adalah:
- pilih **`Split Capsules`** kalau mau perubahan yang aman dan elegan
- pilih **`Sidecar Rail`** kalau mau overlap paling bersih saat nested node banyak

Kalau kamu setuju, langkah implementasi saya nanti akan begini:
- toolbar dan label node tetap **editor-only**
- tidak menyentuh style parser frontend
- tidak menambah padding/margin real ke node content
- semua helper seperti `Container Area`, `Column 1`, `Drop here` saya jaga tetap non-layout-affecting

Kalau mau, sekarang kamu pilih arah finalnya: **`Split Capsules`** atau **`Sidecar Rail`**, lalu saya implementasikan ke builder asli dengan backup dulu.
