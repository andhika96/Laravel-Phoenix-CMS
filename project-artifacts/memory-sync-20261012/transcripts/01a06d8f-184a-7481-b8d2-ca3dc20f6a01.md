## 2026-09-05 01:20:40 WIB — Laporan akhir assistant

Sudah diperbaiki. Penyebabnya bukan `ArticleFrontendController`, Vue pagination, atau detail renderer, tetapi CSS global Arunika Lucent yang mengunci `body` pada tinggi viewport dan mematikan vertical scroll.

## Root cause

Pada dua halaman live, struktur dan computed style menunjukkan:

```text
body class="ph-theme-arunika-lucent"
height: 100vh
overflow: hidden
```

Sementara kontennya lebih tinggi dari viewport:

| Halaman | Sebelum fix | Hasil |
|---|---:|---|
| `/article` | `body scrollHeight: 2468`, `clientHeight: 720`, `scrollY` tetap `0` | Tidak bisa scroll |
| `/article/load-test-20260825-00001` | `body scrollHeight: 1340`, `clientHeight: 720`, `scrollY` tetap `0` | Tidak bisa scroll |

`main` Article sendiri memiliki `overflow: visible`, jadi masalahnya memang berada pada parent `body`.

Sumber penyebabnya ada pada rule global di:

[arunika_lucent.css:221-233](D:/Laragon/www/laravel-13-phoenix/public/assets/css/themes/arunika_lucent/arunika_lucent.css:221)

```css
body {
    height: 100vh;
    overflow: hidden;
}
```

Frontend layout Lucent tidak memakai `.ph-app-shell`, sedangkan admin layout memakai `.ph-app-shell` sebagai internal scroller. Jadi override perlu dibatasi hanya untuk layout non-admin.

## Fix yang diterapkan

Saya menambahkan satu rule scoped di:

[arunika_lucent.css:5131-5137](D:/Laragon/www/laravel-13-phoenix/public/assets/css/themes/arunika_lucent/arunika_lucent.css:5131)

```css
body.ph-theme-arunika-lucent:not(:has(.ph-app-shell))
{
    height: auto;
    min-height: 100%;
    overflow-y: auto;
}
```

Efeknya:

- frontend Article dapat mengikuti tinggi konten;
- `overflow-y` kembali aktif;
- horizontal overflow tetap mengikuti `overflow-x: hidden` dari rule existing;
- admin Lucent yang mempunyai `.ph-app-shell` tidak terkena override ini;
- tidak perlu mengubah Blade Article, controller, Vue runtime, atau pagination.
