# Plan: Styling Per-Column Grid v2.3

## Ringkasan

Tambahkan styling per-column untuk:

- Standalone `Grid`
- `Layout Container` dengan `displayType=grid`

Model Grid/Flex dan struktur flat `columns[]` tetap dipertahankan. `Row Grid`, Flexbox subcontainer, dan hover state tidak termasuk fase ini.

## Perubahan utama

### 1. Data dan inheritance

Tambahkan:

```json
{
  "columnStyles": [
    {
      "borderType": "none",
      "borderWidthTop": "0px",
      "borderWidthRight": "0px",
      "borderWidthBottom": "0px",
      "borderWidthLeft": "0px",
      "borderColor": "transparent",
      "borderRadiusTL": "0px",
      "borderRadiusTR": "0px",
      "borderRadiusBR": "0px",
      "borderRadiusBL": "0px",
      "bgType": "none"
    }
  ],
  "columns": [
    {
      "id": "cell-1",
      "children": [],
      "styleOverrides": {}
    }
  ]
}
```

- `columnStyles[index]` menjadi default untuk track `Column 1`, `Column 2`, dan seterusnya.
- `styleOverrides` menyimpan override sparse per cell.
- Inheritance per field: `cell override → track style → Grid default`.
- Responsive berlaku pada track dan cell: Desktop, Tablet, Mobile.
- Nilai override kosong berarti inherit.
- Tombol `Reset to Column Style` menghapus seluruh override cell.
- Saat column dihapus, style track terkait ikut dihapus; child content tetap mengikuti mekanisme deletion Grid yang sudah ada.
- Node lama tanpa style baru tetap valid dan otomatis memakai defaults.

### 2. Sidebar UI

Pada `Column Structure`:

- Row `Column 1` menjadi selectable dan expandable.
- Expand menampilkan `Row 1`, `Row 2`, dan seterusnya.
- Track dan cell aktif diberi highlight.
- Klik target otomatis membuka tab `Style`.
- Header Style menampilkan target aktif, misalnya:
  - `Column Style — Column 1`
  - `Cell Override — Column 1 / Row 2`
- Tampilkan indikator jika cell memiliki custom override.
- Tombol delete column tetap mempertahankan guard dan confirmation yang ada.

Control style:

- Border Type: `None`, `Solid`, `Double`, `Dotted`, `Dashed`, `Groove`.
- Border Width: four-side, unit, link/unlink.
- Border Color: Coloris.
- Border Radius: four-corner, unit, link/unlink.
- Background penuh: None, Color + opacity, Gradient, Image.
- Tidak ada Hover state pada fase pertama.

### 3. Canvas dan frontend

- Buat resolver style bersama di `app.js` untuk menghitung effective style track/cell.
- Terapkan style ke setiap `.el-grid-col`, bukan membuat wrapper track baru.
- Preserve grid gap, sequential lock, nested Grid, DnD, dan cell structure.
- Tambahkan penanda track/cell pada DOM agar responsive CSS dan override cell dapat ditargetkan dengan aman.
- Sinkronkan behavior pada:
  - `grid/Settings.vue`
  - `container/Settings.vue`
  - `app.js`
  - `grid.blade.php`
  - `container.blade.php`
  - renderer helper di `render_node.blade.php`
- Gunakan validator CSS/color/unit yang sudah ada agar nilai invalid tidak merusak frontend.

Referensi Elementor resmi tetap menjadi acuan istilah/layout, tetapi source aktif dan screenshot lokal menjadi sumber kebenaran implementasi. [Elementor Flexbox playground](https://playground.elementor.com/demo/flexbox/) saat ini meminta login ulang ketika dibuka.

## 2026-08-18 23:00:04 WIB — Laporan akhir assistant

Ya, saya setuju: untuk Flexbox tidak perlu menambahkan model `columnStyles` atau `styleOverrides`.

Struktur Flexbox kita sudah tepat:

```text
Flexbox Parent
├── Child Container 1
│   └── children
└── Child Container 2
    └── children
```

Setiap child Container adalah node nyata, sehingga sudah memiliki:

- Layout
- Style
- Advanced
- Responsive settings
- Width dan edge-resize
- Frontend rendering sendiri

Source aktif juga sudah mendukung list `Child Containers`; klik child memanggil `selectNode(child, { revealPanel: true })`, sehingga sidebar seharusnya langsung berpindah ke settings child tersebut.

Jadi kontraknya sebaiknya:

- Style parent Flexbox mengatur arrangement: direction, gap, justify, align, wrap.
- Style child Container mengatur box-nya sendiri: background, border, radius, padding, margin, typography, dan Advanced.
- Tidak ada style override tambahan di parent.
- Tidak ada duplikasi data style antara parent dan child.

Yang mungkin perlu kita audit hanya UX/runtime, bukan menambah fitur styling baru:

1. Klik `Container 1` dari list benar-benar membuka settings child.
2. Header/sidebar menunjukkan child yang sedang aktif.
3. Style yang diubah hanya memengaruhi child tersebut.
4. Width responsive dan shared-edge resize tetap konsisten.
5. Canvas dan frontend parser menghasilkan tampilan yang sama.

Rekomendasi saya: Flexbox kita perlakukan sebagai audit parity dan polish selection saja. Kalau runtime membuktikan semua alur tersebut sudah benar, tidak perlu perubahan source tambahan untuk styling Flexbox.

Diskusi berikutnya paling tepat adalah memastikan apakah label list tetap `Container 1`, atau ingin dibuat lebih kontekstual seperti `Column Container 1`.
