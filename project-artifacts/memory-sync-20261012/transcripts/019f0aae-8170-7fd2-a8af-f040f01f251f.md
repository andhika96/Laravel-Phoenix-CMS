## 2026-06-28 03:05:52 WIB — Laporan akhir assistant

Itu bukan karena GitLab-nya. Errornya jelas dari lokal repo:

`Unable to create ... .git/index.lock: File exists`

Artinya Git mau membuat file lock untuk proses `git add`, tapi file `.git/index.lock` sudah ada. Biasanya penyebabnya:

1. Proses Git sebelumnya belum selesai atau crash.
2. Terminal/VS Code/Git GUI sebelumnya sempat menjalankan Git lalu terputus.
3. SSD portable dicabut/pindah PC saat Git masih punya lock.
4. File lock lama tertinggal di folder `.git`.

Karena SSD-nya pindah dari PC kantor ke laptop, kemungkinan besar ini **stale lock file** dari proses Git lama, bukan proses aktif.

Langkah aman:

```bash
cd /e/Apps/Laragon/www/newmg
git status
rm -f .git/index.lock
git status
git add .
```

Atau dari PowerShell:

```powershell
Remove-Item -LiteralPath "E:\Apps\Laragon\www\newmg\.git\index.lock"
```

Yang penting: **hapus hanya `index.lock`, jangan hapus `index`**.

Sebelum hapus, pastikan tidak ada proses Git lain yang sedang jalan: tutup VS Code, Git Bash lain, SourceTree/GitKraken, Laragon terminal lain, lalu coba hapus file lock itu. Setelah itu lanjut:

```bash
git add .
git commit -m "your message"
git push
```

Kalau setelah dihapus muncul lagi terus, berarti ada aplikasi lain di laptop yang sedang otomatis membaca repo, biasanya VS Code Source Control, Git GUI, antivirus, atau proses Git yang nyangkut.

## 2026-06-28 03:22:19 WIB — Laporan akhir assistant

Iya, untuk GitLab sekarang lebih aman anggap **password akun tidak dipakai lagi untuk `git pull` lewat HTTPS**. Dari pesan error itu GitLab menolak HTTP Basic auth karena password salah, token expired/revoked, scope kurang, atau memang wajib pakai token.

Untuk server AWS EC2 production, pilihan paling cocok:

**Opsi terbaik: Deploy Token khusus server**
Ini lebih aman daripada Personal Access Token karena aksesnya bisa dibuat hanya untuk repo itu dan hanya `pull`.

Di GitLab:

1. Buka project `ibig/mg-motor-id-v2`
2. Masuk `Settings > Repository`
3. Cari `Deploy tokens`
4. Klik `Add token`
5. Isi misalnya:
   - Name: `ec2-mgmotor-production`
   - Username: boleh custom, misalnya `ec2-mgmotor-readonly`
   - Expiration: isi tanggal, atau kosong kalau GitLab mengizinkan
   - Scope: centang `read_repository`
6. Klik `Create deploy token`
7. Simpan **username** dan **token/password** yang muncul. Setelah halaman ditutup, token tidak bisa dilihat lagi.

Lalu di EC2:

```bash
cd /var/www/html/mgmotor.id
git remote set-url origin https://ec2-mgmotor-readonly@gitlab.com/ibig/mg-motor-id-v2.git
git pull origin main
```

Saat diminta password, paste **deploy token**, bukan password GitLab.

Alternatif kalau mau pakai akun pribadi:

GitLab avatar kanan atas > `Edit profile` > `Access > Personal access tokens` > `Generate token` > pilih scope:

- Untuk pull saja: `read_repository`
- Kalau juga push: `write_repository`

Lalu di server:

```bash
git remote set-url origin https://andhika.adhitia96@gitlab.com/ibig/mg-motor-id-v2.git
git pull origin main
```

Password yang dimasukkan = **Personal Access Token**, bukan password akun.

Jangan taruh token langsung di URL kalau bisa, karena bisa masuk history terminal. Kalau setelah token benar masih gagal, kemungkinan EC2 menyimpan credential lama. Cek dulu:

```bash
git config --global --get credential.helper
```

Kalau pakai credential cache/store, hapus credential GitLab lama lalu pull ulang.

Referensi resmi GitLab: Personal Access Token untuk Git over HTTPS memakai token sebagai password, dan scope `read_repository` untuk pull private repo; Deploy Token juga mendukung Git command dengan scope `read_repository`.  
Sources: [GitLab Personal Access Tokens](https://docs.gitlab.com/user/profile/personal_access_tokens/), [GitLab Deploy Tokens](https://docs.gitlab.com/user/project/deploy_tokens/), [GitLab HTTP Basic Access Denied](https://docs.gitlab.com/topics/git/troubleshooting_git/#error-on-git-fetch-http-basic-access-denied).

## 2026-06-28 03:32:44 WIB — Laporan akhir assistant

Iya, kalau repo GitLab-nya memakai akun user biasa dan server diminta login sebagai `andhika.adhitia96`, maka yang dipakai memang **Personal Access Token (PAT)** sebagai pengganti password.

Paling aman untuk kebutuhan `pull` dari EC2:

- Token type: **Personal Access Token**
- Scope cukup: `read_repository`
- Username saat `git pull`: username GitLab kamu
- Password saat `git pull`: isi dengan PAT, bukan password akun

Contoh:

```bash
git pull origin main
```

Lalu:

```text
Username: andhika.adhitia96
[REDACTED_SECRET]
```

Kalau nanti server masih memakai password lama yang tersimpan, hapus credential lama atau update remote/credential helper. Jangan share token itu, karena token tersebut setara akses akun sesuai scope yang kamu beri.
