## Apakah Esri World Imagery berbayar?

Esri menggunakan model **freemium**, bukan langsung berbayar sejak tile pertama.

Menurut harga resmi ArcGIS Location Platform saat ini:

- **2 juta basemap tiles gratis per bulan**.
- Setelah melewati batas tersebut: **US$0,15 per 1.000 tile**.
- Jika perusahaan sudah memiliki subscription ArcGIS Online, penggunaan basemap tertentu termasuk dalam subscription.
- Integrasi resmi memerlukan akun ArcGIS Location Platform/ArcGIS Online dan access token atau API key. [Dokumentasi harga resmi Esri](https://developers.arcgis.com/rest/basemap-styles/), [ArcGIS Location Platform Pricing](https://location.arcgis.com/pricing/)

Untuk aplikasi internal seperti CMS BUM, kuota 2 juta tile kemungkinan cukup besar. Sebagai gambaran kasar, satu tampilan awal map mungkin meminta sekitar 4–12 tile, tetapi jumlah sebenarnya meningkat jika pengguna sering zoom dan pan. Karena browser menyimpan tile dalam cache, tile yang sama tidak selalu diminta ulang.

Integrasi Esri sebenarnya **tidak terlalu rumit secara kode**. Pada Leaflet hanya perlu membuat satu `L.tileLayer()` tambahan. Bagian ekstra dibandingkan OSM adalah:

- membuat akun/API key Esri;
- membatasi API key hanya untuk domain aplikasi;
- menyimpan konfigurasi key dengan benar;
- menampilkan attribution Esri dan penyedia imagery;
- memonitor penggunaan agar tidak melewati free tier.

Endpoint resmi World Imagery yang didokumentasikan Esri memakai access token. [Dokumentasi World Imagery Esri](https://developers.arcgis.com/rest/basemap-styles/service-data/)

Codebase memang sudah mempunyai URL lama `server.arcgisonline.com` tanpa token, dan endpoint itu masih merespons ketika saya uji. Tetapi saya **tidak menyarankan menggantungkan implementasi produksi baru pada endpoint lama tersebut sebagai layanan gratis permanen**. Ia bisa tetap bekerja, tetapi bukan jalur resmi modern untuk pengelolaan kuota, key, dan billing.

## Apakah bisa memakai OSM?

Bisa, bahkan jauh lebih sederhana karena OSM **sudah dimuat oleh halaman Map Pokok sekarang**. Saat ini OSM berada di bawah raster MBTiles dan tertutup oleh raster tersebut.

Implementasi pilihan kedua memakai OSM hanya perlu:

```text
- tampilkan MBTiles di atas OSM

Peta Jalan
- hapus MBTiles
- biarkan OSM terlihat
```

Tidak perlu:

- akun baru;
- API key;
- token;
- route baru;
- endpoint backend baru;
- dependency baru;
- biaya provider baru.

Namun label opsi keduanya harus **“Peta Jalan”** atau **“OpenStreetMap”**, bukan “Satelit”, karena tampilannya berupa jalan, nama lokasi, sungai, dan informasi kartografis—bukan foto udara.

## Apakah OSM benar-benar gratis?

Data OpenStreetMap bersifat terbuka, tetapi server tile publik `tile.openstreetmap.org` bukan hosting tanpa batas. Kebijakan resminya menyatakan:

- wajib menampilkan `© OpenStreetMap contributors`;
- harus memakai URL tile yang benar;
- browser harus mengirim referer normal;
- caching harus dihormati;
- tidak boleh melakukan bulk download, scraping, prefetch area luas, atau membangun MBTiles dari server publik OSM;
- layanan bersifat best-effort, tanpa SLA, dan akses dapat dibatasi jika pemakaian terlalu berat. [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)

Untuk pemakaian normal pada halaman internal—pengguna membuka map, zoom, dan pan secara wajar—OSM publik umumnya merupakan pilihan yang paling sederhana. Jika nanti pengguna dan trafiknya sangat besar, barulah dipertimbangkan provider OSM komersial atau tile server sendiri.

## Pilihan yang realistis

### Opsi A — Map Pokok + OpenStreetMap

Ini rekomendasi saya jika tujuan utamanya adalah menyediakan dua cara melihat data pokok dengan biaya dan kompleksitas minimum:

```text
Tipe Tampilan Peta
- Map Pokok
- Peta Jalan
```

Keuntungan:

- tidak berbayar untuk kebutuhan normal;
- tidak perlu akun atau API key;
- OSM sudah ada dalam source aktif;
- perubahan sangat kecil;
- tidak ada risiko token bocor;
- jika jaringan internet bermasalah, Map Pokok lokal masih dapat bekerja melalui MBTiles.

Kekurangan:

- bukan citra satelit;
- detail area kebun pada OSM mungkin sedikit;
- tile server publik tidak memiliki SLA.

### Opsi B — Map Pokok + Esri World Imagery

Gunakan ini jika pengguna benar-benar perlu melihat kondisi visual permukaan tanah dari foto udara/satelit:

```text
- Satelit
```

Keuntungan:

- benar-benar citra satelit/foto udara;
- membantu membandingkan posisi pokok, jalan, blok, sungai, dan kondisi lapangan;
- integrasi Leaflet tetap sederhana;
- free tier resmi saat ini cukup besar.

Kekurangan:

- memerlukan akun dan API key Esri;
- penggunaan harus dipantau;
- bisa berbayar apabila melewati 2 juta tile per bulan;
- resolusi dan usia imagery berbeda menurut wilayah;
- membutuhkan internet.

### Opsi C — Satellite MBTiles lokal

Citra satelit diunduh/disiapkan sebagai MBTiles lalu dilayani dari server sendiri.

Keuntungan:

- tidak bergantung pada koneksi provider ketika sudah tersedia;
- tidak ada biaya per permintaan tile;
- data dapat dikunci pada tanggal tertentu.

Kekurangan:

- proses memperoleh dan menyiapkan imagery lebih rumit;
- ukuran file dapat sangat besar;
- harus memastikan izin/lisensi imagery;
- imagery tidak otomatis diperbarui;
- lebih rumit daripada Esri maupun OSM.

Saya tidak merekomendasikan opsi ini untuk tahap awal kecuali perusahaan sudah mempunyai file citra drone/satelit berlisensi yang memang ingin digunakan.

## Rekomendasi saya

Jika kebutuhan Anda hanya **“ingin ada tampilan map alternatif selain peta pokok sekarang”**, gunakan:

```text

2. Peta Jalan (OpenStreetMap)
```

Ini solusi paling sederhana, tidak membutuhkan pembayaran, dan OSM-nya sudah terdapat di halaman sekarang.

Jika kebutuhan Anda secara spesifik adalah **melihat foto udara atau tutupan lahan sebenarnya**, OSM tidak dapat menggantikannya. Untuk itu gunakan:

```text
1. Map Pokok
2. Satelit (Esri World Imagery)
```

Dengan traffic internal, kemungkinan besar pemakaiannya masih berada dalam kuota gratis 2 juta tile per bulan, tetapi sebaiknya tetap menggunakan akun/API key resmi dan memasang usage limit.

Jadi jawaban singkatnya:

- **Esri World Imagery:** freemium; gratis sampai 2 juta tile/bulan, kemudian berbayar.
- **Integrasi Esri:** tidak rumit di kode, tetapi memerlukan akun, key, attribution, dan monitoring.
- **OSM:** bisa dan paling mudah, tetapi hasilnya **peta jalan, bukan satelit**.
- **Rekomendasi paling minimal:** buat dua tipe `Map Pokok` dan `Peta Jalan (OSM)`.
- **Rekomendasi jika citra satelit wajib:** tetap gunakan Esri World Imagery melalui API resmi.

## Tiga pilihan

### 1. Batasi Esri sampai zoom 18

Ini paling jujur dan stabil:

```javascript
maxNativeZoom: 18,
maxZoom: 18,
```

Hasilnya:

- gambar tetap sejernih sumber Esri yang tersedia;
- tidak pernah masuk ke placeholder;
- tombol `+` berhenti pada zoom 18;
- pengguna tidak dapat zoom lebih dekat.

Ini opsi yang saya rekomendasikan jika tetap ingin memakai Esri dan menghindari tampilan rusak.

### 2. Izinkan zoom sampai 22 dengan digital overzoom

Konfigurasinya:

```javascript
maxNativeZoom: 18,
maxZoom: 22,
```

Hasilnya:

```text
Zoom 18 → ukuran asli
Zoom 19 → citra zoom 18 diperbesar 2×
Zoom 20 → diperbesar 4×
Zoom 21 → diperbesar 8×
Zoom 22 → diperbesar 16×
```

Keuntungannya:

- tidak lagi muncul `Map data not yet available`;
- pengguna masih bisa menekan zoom sampai 22;
- jalan atau objek besar masih bisa diperiksa lebih dekat.

Kekurangannya:

- citra semakin blur/pixelated;
- tidak ada detail baru;
- pokok sawit tidak otomatis terlihat lebih tajam;
- image enhancement/CSS tidak dapat mengembalikan detail yang tidak terdapat dalam file sumber.

Ini bisa dipakai sebagai solusi sementara, tetapi tidak memenuhi syarat “zoom lebih dekat dan tetap jernih”.

### 3. Gunakan citra resolusi tinggi milik perusahaan

Ini satu-satunya solusi yang benar-benar memberikan zoom dekat dan tetap tajam.

Sumbernya dapat berupa:

- hasil pemetaan drone;
- orthomosaic;
- GeoTIFF georeferenced;
- citra udara vendor;
- citra satelit komersial yang mempunyai cakupan detail lebih tinggi untuk estate tersebut.

Alurnya:

```text
Drone / GeoTIFF / Orthomosaic
              ↓
Pemeriksaan CRS dan georeference
              ↓
Konversi menjadi MBTiles/COG
              ↓
Tile endpoint aplikasi
              ↓
Leaflet
```

Untuk pemeriksaan individu pokok sawit, idealnya sumber citra memiliki resolusi sekitar beberapa sentimeter hingga puluhan sentimeter per pixel, tergantung detail yang ingin dilihat. Pada resolusi itu, zoom 20–22 mempunyai data nyata yang dapat ditampilkan—bukan pembesaran digital.

Kelebihannya:

- detail pokok, jalan kebun, TPH, drainase, dan batas blok bisa lebih jelas;
- dapat dipakai offline/lokal;
- tidak tergantung coverage Esri;
- tidak ada biaya per tile jika file dimiliki perusahaan;
- tanggal pengambilan citra diketahui.

Kekurangannya:

- memerlukan file imagery;
- ukuran MBTiles bisa besar;
- harus memastikan CRS/georeference benar;
- perlu proses pembaruan apabila ada penerbangan/pemetaan baru.

Untuk sementara:

```text

maxNativeZoom = 18
maxZoom       = 22
```

Dengan begitu:

- pengguna tetap bisa zoom sampai 22;
- placeholder tidak akan muncul;
- Leaflet memperbesar citra zoom 18;

## 1. Buat session token

Request pertama:

```http
POST https://tile.googleapis.com/v1/createSession?key=[REDACTED_SECRET]
Content-Type: application/json
```

Body:

```json
{
  "mapType": "satellite",
  "language": "id",
  "region": "ID",
  "imageFormat": "jpeg"
}
```

Contoh menggunakan `curl`:

```bash
curl -X POST \
  "https://tile.googleapis.com/v1/createSession?key=[REDACTED_SECRET] \

```

Response Google akan berbentuk seperti:

```json
{
  "session": "SESSION_TOKEN_DARI_GOOGLE",
  "expiry": "1760000000",
  "tileWidth": 256,
  "tileHeight": 256,
  "imageFormat": "jpeg"
}
```

Google mewajibkan session token untuk request 2D satellite tiles. Token tersebut berlaku dalam jangka waktu tertentu dan harus dikirim pada request tile berikutnya. ## 2. Request tile satelit

Format URL lengkapnya:

```text
https://tile.googleapis.com/v1/2dtiles/{z}/{x}/{y}?session={SESSION_TOKEN}&key=[REDACTED_SECRET]
```


Karena kedua branch sudah bercabang, Git tidak mau memilih sendiri apakah harus merge atau rebase. Mengulang `git pull origin main` beberapa kali akan menghasilkan error yang sama karena strategi pull belum ditentukan.

## Periksa dulu kondisi VPS

Di terminal VPS, jalankan read-only:

```bash
cd /www/wwwroot/itbumdev.web.id
git status --short --branch
git fetch origin
git rev-list --left-right --count main...origin/main
git log --oneline --decorate --graph --all -n 20
```

Arti hasil `git rev-list`:

```text
A    B
```

- `A` = jumlah commit yang hanya ada di branch `main` VPS.
- `B` = jumlah commit yang hanya ada di `origin/main` GitLab.

Jangan langsung menjalankan `git reset --hard` sebelum melihat hasil ini.

## Pilihan penyelesaian

### Jika commit lokal VPS harus dipertahankan

Gunakan rebase:

```bash
git pull --rebase origin main
```

Ini mengambil commit dari GitLab, lalu menempatkan commit lokal VPS di atasnya. Jika ada konflik, Git akan berhenti dan meminta penyelesaian manual.

Setelah konflik selesai:

```bash
git add path/file-yang-sudah-diperbaiki
git rebase --continue
```

Untuk menjadikan rebase sebagai default repository tersebut:

```bash
git config pull.rebase true
```

### Jika ingin membuat merge commit

Gunakan:

```bash
git pull --no-rebase origin main
```

Ini mempertahankan dua jalur history dan membuat satu merge commit. Untuk project deployment, history-nya biasanya lebih berisik dibanding rebase, tetapi aman jika commit lokal memang perlu dipertahankan.

Untuk menjadikannya default:

```bash
git config pull.rebase false
```

### Jika VPS harus persis sama dengan GitLab

Ini biasanya cocok untuk checkout deployment yang tidak boleh memiliki commit lokal. Namun ini destruktif terhadap commit lokal VPS.

Sebelum melakukan itu, buat backup branch:

```bash
git fetch origin
git branch backup/vps-main-before-reconcile-$(date +%Y%m%d-%H%M%S)
git reset --hard origin/main
```

Perintah ini akan membuang commit yang hanya ada di branch VPS dari branch aktif. File untracked juga perlu diperiksa terpisah karena `reset --hard` tidak menghapus semua untracked file.
